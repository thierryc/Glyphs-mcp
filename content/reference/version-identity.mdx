`sidecarVersion` and `bridgeVersion` are coordinated product versions. The lean
interface revision identifies the seven-tool contract; the bridge protocol
identifies the sidecar/native message contract. The dated MCP transport version
is negotiated separately during initialization. These values need not match.
Independent Curve Inspector and Reference Inspector versions do not determine
the MCP product version.

## Verify an installation

Compare the freshly observed `get_status` result with that installation's
manifest and receipt:

- `release` identifies the product/release version, channel, beta number and build.
- `interface` and `interfaceVersion` identify the lean interface. Check advertised
  `readCapabilities` and `jobKinds` for the requested workflow.
- Sidecar `runtimeId` combines its release with a short file fingerprint;
  `codeHash` gives the complete fingerprint. Check `bridge.release`,
  `bridge.runtimeId` and `bridge.codeHash` independently.
- `bridge.host` identifies the native application by bundle identifier, version
  and build. The Beta 4 payload accepts `com.GeorgSeifert.Glyphs4`. Glyphs 3
  uses its separate v1.11.0 distribution.

The fingerprint is computed from component files at initialization. It is not a
hash of in-memory code, and changed installed files do not prove that the running
process loaded them. Missing identity is unavailable evidence; differing expected
and reported component hashes require investigation. Do not fabricate a match.

The MCP endpoint remains `http://127.0.0.1:9680/mcp/` by default. Use the configured
endpoint and **Edit → Glyphs MCP Server…** in the intended host. Verifying identity
needs no document discovery or Save. Dirty-font state is unrelated to interface
identification. During font work, retain the connection's known document ID and
read fresh data; rediscover after stale-ID rejection or a known host/bridge restart.

## Source, installation and release evidence

A source version states what a checkout is preparing. An installation receipt
states which files were installed. A live status response identifies the loaded
components' initialization-time fingerprints. Developer ID, notarization,
Gatekeeper and signed-update acceptance require results for the exact final
artifacts. None of these is established by a marketing label or a docs build.

The current candidate has local qualification records; signed distribution
qualification remains separate. Public availability follows the beta launch
process. A configured URL does not prove that a feed or release is published.

Beta 4 uses tag `v2.0.0-beta.4` and branch `lit/v2-beta`. Its feed is
`https://raw.githubusercontent.com/thierryc/Glyphs-mcp/lit/v2-beta/appcast.xml`.
Expected beta artifacts include `Glyphs-MCP-2.0.0-beta.4.dmg` and
`Glyphs-MCP-2.0.0-beta.4.zip`. A beta is a prerelease with `make_latest=false`;
never publish `Glyphs-MCP-latest.dmg` for it. Stable releases use their separate
feed and release process. Installer builds increase across beta and final
releases; changing the label does not make an older build newer.
