# Glyphs MCP 2.0.0

Glyphs MCP 2.0 is a breaking, Glyphs 4-focused architectural reset. V1 and
Glyphs 3 remain on the signed v1.11 runtime. V2 was not public before this
reset, so removed tools have no aliases or transition wrappers.

## Highlights

- The model-visible surface is 18 generic tools for discovery, canonical
  reads, constraints, immutable previews, verified apply, history, offline
  Knowledge, permanent Python fallback, export/save, UI, and runtime repair.
- Knowledge supplies pinned cited facts, managed skills supply type-design and
  Glyphs expertise, and tools supply mechanics. Runtime mutation code contains
  no spacing taste, category heuristics, or workflow solver.
- Canonical schema v6 classifies the saved semantic state covered by the pinned
  Glyphs File Format v4 source while keeping volatile provenance and UI-session
  state outside fingerprints.
- `EntitySelector`, `Projection`, `Constraint`, and `ChangeOperation` form one
  closed reusable language across glyph, layer, master, kerning, OpenType,
  instance, and export work.
- `preview_change` stores exact identities, dependencies, fingerprints,
  normalized physical operations, semantic diff, and constraint evidence.
  `apply_change` consumes that patch without rerunning planning.
- Staged Python runs once against a detached document and returns the same
  immutable preview as declarative writes. Python remains permanently
  available for unsupported reads, document edits, UI, APIs, files, and other
  external effects.
- Every document mutation uses snapshot, detached simulation, one live apply,
  complete read-back, verification, rollback on failure, audit, history, and
  conflict-aware revert. Nothing saves implicitly.
- The offline Knowledge corpus is deterministic, searchable, version-aware,
  and cited. Updates occur through reviewed builds rather than runtime network
  access.
- `skills/` is the only authored expertise source; the plug-in skill package is
  generated and checked for exact equality.

## Effect boundaries

`save_document`, `apply_export`, `open_document_view`, `repair_runtime`, and
`execute_python(mode="live_open_world")` are explicit boundaries. Files,
network calls, subprocesses, preferences, saves, UI state, and other external
effects are never described as transactionally reversible merely because a
document checkpoint exists.

The Change Log is process-local working history, not a replacement for source
control or saved-file backups. Conflicting later edits are refused rather than
overwritten.

## Qualification

Release candidates must pass deterministic schema, selector, constraint,
preview/apply equivalence, patch inversion, mutation, rollback, pagination,
Knowledge, Python, routing, skill synchronization, and bundle tests. Separate
disposable Glyphs 4 gates must restore exact canonical and native baselines and
prove that no implicit save occurred. Source-level tests do not substitute for
that live evidence.

Publication remains gated by Developer ID signature, notarization, stapling,
Gatekeeper, checksums, deterministic payload assembly, and isolated simulated
installation for the exact signed tag.
