product label, a skill name or the Glyphs display name cannot identify an MCP
interface by itself. The current lean catalog has eighteen tools; the v1 catalog
and its pinned Glyphs 3 skills remain separate.

`sidecarVersion` and `bridgeVersion` are coordinated product versions. The lean
interface revision identifies the eighteen-tool contract; the bridge protocol
identifies the sidecar/native message contract. The dated MCP transport version
is negotiated separately during initialization. These values need not match.
The sixth job, `outline_edit`, is additive and appears only when the bridge
advertises `outline.edit.v1`; an older coordinated installation reports five.
Within that job, native shape-preserving `remove_node` is advertised separately
through `outline.remove-node.v1`; older bridges retain the other outline
operations but reject that operation before preparation.
The seventh job, `native_action`, appears only with `native.action.v1` and a
nonempty filtered `nativeActions` catalog. Its action list is negotiated with
the exact Glyphs build rather than inferred from protocol or product version.
The eighth and ninth jobs, `feature_compile` and `font_export`, appear only when
their live/saved compiler or static/variable export and verification
capabilities are advertised. They reuse the same job lifecycle and do not add
MCP endpoints.
The tenth job, `dimensions_edit`, appears only with `master.dimensions.edit.v1`.
It edits per-master reference notes; existing values require conversational
overwrite approval, while blank fills do not.
Independent Curve Inspector and Reference Inspector versions do not determine
the MCP product version.

## Verify an installation

Compare the freshly observed `get_status` result with that installation's
manifest and receipt:

- `release` identifies the product/release version, channel, beta number and build.
- `interface` and `interfaceVersion` identify the lean interface. Check advertised
  `readCapabilities`, `writeCapabilities`, `jobKinds` and `nativeActions` for the requested workflow.
- Sidecar `runtimeId` combines its release with a short file fingerprint;
  `codeHash` gives the complete fingerprint. Check `bridge.release`,
  `bridge.runtimeId` and `bridge.codeHash` independently.
- `bridge.host` identifies the native application by bundle identifier, version
  and build. The v2 payload accepts `com.GeorgSeifert.Glyphs4`. Glyphs 3
  uses its separate v1.11.0 distribution.

The fingerprint is computed from component files at initialization. It is not a
hash of in-memory code, and changed installed files do not prove that the running
process loaded them. Missing identity is unavailable evidence; differing expected
and reported component hashes require investigation. Do not fabricate a match.

The MCP endpoint remains `http://127.0.0.1:9680/mcp/` by default. Use the configured
endpoint and **Edit → Glyphs MCP Server…** in the intended host. Verifying identity
needs no document discovery or Save. Dirty-font state is unrelated to interface
identification. During font work, retain the connection's known document ID and
read fresh data; rediscover after stale-ID rejection or a known host/bridge restart.

## Source, installation and release evidence

The unpublished **2.0.2/build 57** candidate uses planned source tag
`v2.0.2`, archive names `Glyphs-MCP-2.0.2.dmg` and `Glyphs-MCP-2.0.2.zip`, and
stable feed `https://raw.githubusercontent.com/thierryc/Glyphs-mcp/main/appcast.xml`.
Published 2.0.1/build 56 has separate signing, notarization and bounded native
acceptance. Its evidence does not qualify the 2.0.2 desktop candidate. Optional
Diffenator and Beztrace packages have bounded signed local Apple Silicon evidence;
hosted assets and supported-platform qualification remain pending. See
[qualification](release-qualification.mdx). Preserve published tags, artifacts and
signed feeds until final candidate verification and separately authorized promotion.

A source version states what a checkout is preparing. An installation receipt
states which files were installed. A live status response identifies the loaded
components' initialization-time fingerprints. Developer ID, notarization,
Gatekeeper and signed-update acceptance require results for the exact final
artifacts. None of these is established by a marketing label or a docs build.

non-Latest GitHub prerelease. Its archived signed appcast describes its
verified public archive. Its exact signed desktop-update/component-migration

evidence and remaining limits are recorded in
[BETA7-VALIDATION.md](https://github.com/thierryc/Glyphs-mcp/blob/v2.0.0/BETA7-VALIDATION.md).
