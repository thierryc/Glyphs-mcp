# Glyphs MCP 2.0 foundation

Glyphs MCP 2.0 is a contract and architecture reset, rebased on signed release
`v1.11.0`. The isolated runtime now covers typed discovery, bounded analysis,
apply-first verified production mutations, staged export, model-visible Python fallback,
and document rollback. It does not replace, load, or modify the installed 1.x
plug-in during source development.

## Invariants

- `/mcp/` remains the canonical local endpoint.
- The server advertises API major 2 independently from its package version.
- Structured content is normative; text is a concise human fallback.
- `documentId` is the durable process-local font target. `legacyIndex` is
  informational during migration and must not become a stored identity.
- Contracts and application services never import GlyphsApp, AppKit,
  Foundation, FastMCP, or Uvicorn.
- The Glyphs adapter captures complete immutable values on the main thread;
  native objects never cross into application or transport layers.
- Public MCP registration derives only from the typed v2 catalog.
- Every typed mutation uses one shared prevalidate/snapshot/apply/read-back/
  verify kernel, never saves implicitly, and emits one apply audit receipt.

## Implemented v2 surface

The canonical package is `src/glyphs-mcp-v2/glyphs_mcp_v2`. It contains:

- versioned result, warning, and error contracts;
- stable document identity binding across fresh PyObjC proxies and first save;
- immutable host and canonical document snapshots;
- a recoverable main-thread execution port;
- Glyphs 3.5/4 collection fallbacks;
- catalog-generated schemas and safety annotations;
- 25 catalog-driven FastMCP operations;
- paginated glyph, instance, kerning, audit, review, and Python-diff results;
- direct glyph, anchor, kerning, spacing, metrics, and compatibility batches
  with detached derived-effect simulation;
- compatibility, metrics-inheritance, anchor, spacing, kerning-coverage, and
  export analysis;
- staged export with destination fingerprints and macOS atomic directory swap;
- detached `GSFont.copy()` Python review, exact confirmation without rerunning
  code, live open-world recovery, and inverse-patch rollback;
- Git-like content-addressed unsaved-session action history, bounded commit
  discovery, conflict-aware semantic revert, a passive Change Log, and an
  independent drawing-only Edit View diff;
- restart-safe Streamable HTTP application construction;
- deterministic source and Plugin Manager payload assembly.

The payload builder writes to `build/v2-runtime/` by default and rejects any
output path outside this worktree. It does not create a live Glyphs link.

## Compatibility and migration

The v2 runtime preserves sound capability names but does not claim exact 1.x
wire compatibility. Migration will replace transient index targeting, legacy
JSON result strings, inconsistent confirmation flags, and unstructured errors.
Removed or redesigned capabilities receive documentation tombstones rather
than ambiguous registered aliases.

The v2 tombstones are:

| 1.x name | v2 replacement |
| --- | --- |
| `ExportDesignspaceAndUFO` | `review_export`, then `export_source_bundle` |
| `get_font_glyphs` | `list_glyphs` |
| `get_font_kerning` | `list_kerning_pairs` |
| `get_font_instances` | `list_instances` |
| `glyphs-mcp-features` | `glyphs-mcp-opentype-features` |
| mutation `review_*_updates` tools | direct `apply_*` with an expected document fingerprint |

None of the old names is registered as a v2 alias. The 1.11 runtime retains its
own tools until an installed runtime is explicitly upgraded and Glyphs is
restarted.

## Python execution and rollback

Read-intent Python reports document and scope violations. Document edits default
to a detached clone and return a deterministic paginated semantic diff. Native
archive deltas from direct execution and independent canonical replay must be
equivalent. Exact confirmation applies only the stored writable patch, verifies
the complete observed result, and never reruns Python. Unsupported staged
fields return bounded roots, counts, and paths.

`live_open_world` remains available for global Glyphs APIs, UI state, unsupported
objects, files, processes, and networking. It uses exact preview, a full clone,
and a private serialized checkpoint, but reports external effects as
unverifiable and timeout enforcement as cooperative. Automatic rollback is
available only for a complete supported observed document diff. Otherwise a
separate recovery document can be opened. Later edits are never overwritten.

Git protects source history; it is not used for runtime rollback because it
cannot represent unsaved live documents, multiple open fonts, or external
effects.

Runtime action history follows Git's immutable-object and revert concepts but
does not invoke Git. See [Canonical change history](./canonical-change-history)
for its save lifetime, storage model, UI separation, and performance gates.

`lit/next-1.x` remains eligible for critical defects, security and packaging
hardening, Glyphs host compatibility, pure font engines, deterministic
fixtures, SDK documentation, and contract-neutral Reporter models. V2 request
and result contracts, stable IDs, registration, application services, and
breaking catalog changes do not flow back to 1.x.

## Milestone order

1. Complete: stable IDs, contracts, transport, containment, and assembly.
2. Complete for the production canonical model: snapshots, pagination,
   fingerprints, semantic diffs, transactions, audit, Python, and rollback.
3. Complete for the current production milestone: compatibility, metrics,
   anchors, spacing, kerning, instances, export, and synchronized skills.
4. In progress: Glyphs 4 disposable verification of the verified apply-first
   kernel. Glyphs 3.5 remains on signed v1.11 until a later authorized live gate.
5. In progress: updates to existing feature/class/prefix code entries now use
   the verified apply-first kernel. Collection membership changes, master
   duplication, instance mutation, installer integration, and the
   release-candidate matrix remain deferred.

Every milestone must pass focused tests, the complete Python suite, catalog
and schema gates, deterministic payload assembly, and `git diff --check`.
Live Glyphs checks use disposable fonts and remain separate from ordinary
source implementation. The guarded
`glyphs_mcp_v2.live_gates.verify_copy_and_make_copy` helper refuses fonts that
do not use the `Glyphs MCP V2 Disposable` family-name prefix.
