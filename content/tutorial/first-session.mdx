---
title: Your first v2 session
---

Open a **disposable copy** of a font in Glyphs for this first session. The
conversation will help with saving if necessary; preparation still requires
an explicitly identified saved, clean font.
For a new font, start with [creation and saving](../workflows/fonts-and-saving.mdx).

## Connect and identify the font

Ask your connected client:

> Check Glyphs MCP status and identify my disposable font. Do not change it yet.

The client uses `get_status` and `list_documents` when the connection and target
are not already known. Check the font name and distinguishing path. You do not
need to enter document IDs or tool names.

## Preview a small change

Choose a glyph that exists in the test font. For example:

> Preview a width increase of 8.125 font units for H only. Show me the proposal before applying it. Wait for my answer after application too.

The client uses `start_edit_workflow` with `mode="preview"`, the retained document,
`kind="width_delta"`, `glyphs=["H"]`, `delta=8.125`, `auto_keep=false`, and a stable idempotency key.
If the font is dirty, choose **Save and continue** to save existing work once
and prepare the preview. For a new font, choose **Save As…**, or save manually
in Glyphs and reply **Check and continue**. Saving includes the whole font.

Review the proposal's changes and any warnings. Preparation changes nothing
in the open font. This width operation targets H's layers; an omitted glyph
list means the full font. Decisions use native questions when available, or
ordinary chat. Related missing information can be grouped into one question
request. A card is optional when its evidence or controls help; it uses the same
retained workflow. See [conversation edits](conversation-edits.mdx) for client support.

## Apply and review

Choose **Apply changes**, or say it in the conversation. The assistant maps the
reply to the current action without requiring IDs or JSON. Inspect H in Glyphs,
read its width through the client, and try native Undo and Redo on that glyph.
After verification, the conversation says **Changes applied.** Routine progress,
success and errors stay in the conversation.

An ordinary request such as “Increase H's width by 8.125” uses apply mode and
applies a complete proposal automatically. Preview requests and proposals with
warnings or incomplete coverage wait for review.

## Finish the experiment

Choose **Undo these changes** to reverse this edit. Conflicts
with later edits are reported. **Keep changes without saving** leaves the edit
unsaved and ends the workflow's selective recovery offer; native Undo/Redo
remains available. To persist the result, choose **Save font** or **Save As…**.
This is a separate save authorization from Save and continue; it saves the whole
current font. After verification, the conversation says **Font saved.**

If a call times out, check the existing workflow. Do not submit the same edit
again under a new request. Closing an optional card does not cancel authorized work.
Every choice remains usable through ordinary conversation when the UI is absent.

The original low-level `start_job`, `get_job`, `apply_job`, `accept_job` and
`discard_job` tools remain available with unchanged signatures and guards; see
the [tool reference](../reference/command-set.mdx) and
[Safety and recovery](../concepts/safety-model.mdx).
