---
title: How v2 works
---

V2 separates expensive preparation from live editing. The AI client uses seven MCP tools; the native bridge supplies bounded reads and applies explicit changes on Glyphs' main thread.

| Part | Responsibility |
| --- | --- |
| AI client and skills | Choose a supported workflow, scope it and review its evidence with the designer. |
| Sidecar | Serve MCP, manage jobs, copy saved sources and run external preparation. |
| Private native worker | Use `glyphs-cli` with the selected Glyphs application to measure or prepare detached font data. |
| Bridge | Read explicit targets, check preconditions, apply changes in chunks and manage exact recovery and native history. |
| Companions | Draw cached curve or reference overlays independently of the MCP client. |

The bridge never saves a font. Source copying and whole-font preparation run outside the editor. Live writes yield to Cocoa between chunks so the canvas can remain responsive.

## One job, one identity

`start_job` prepares an external result and returns a job ID. `get_job` returns progress and evidence. `apply_job` applies the stored result to the matching saved document. `discard_job` cancels preparation or reverses still-current affected targets. Repeated apply or discard requests for the same ongoing operation do not create duplicate native operations.

The bridge shares per-document ownership across apply, discard and rollback. A competing operation cannot open a second Undo scope or alter the owner's state.

## Native editing remains central

Save accepts the reviewed result. Undo and Redo use native per-glyph history. Revert uses Glyphs' own saved-document workflow. The Reference Inspector compares against a selected source; it is not a log of tool calls or an acceptance interface.
