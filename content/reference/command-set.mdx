title: The seven v2 tools
---

This is the current private **Glyphs MCP 2.0.0 Beta 1** tool contract. Product release
`2.0.0-beta.1` is distinct from interface revision `1`, bridge protocol `1`, and
the separately negotiated MCP transport version. Inspect `get_status` for
independent sidecar/bridge identities and negotiated `readCapabilities`.

| Tool | Arguments | Purpose |
| --- | --- | --- |
| `get_status` | None | Read sidecar, worker and bridge availability. |
| `list_documents` | None | Identify open documents and their paths, saved state, edit generation and native `isCurrent` (true/false/null when unavailable). |
| `read_entities` | `document_id`, `entities`, `fields` | Read at most 100 explicit targets per call. |
| `start_job` | `document_id`, `kind`, optional `delta`, `glyphs`, `options` | Prepare a supported job outside the editor. |
| `get_job` | `job_id`, optional `include_preview` | Read current status, summary, report, sample and error details. |
| `apply_job` | `job_id`, optional `include_preview` | Apply the prepared result as a reversible live change. |
| `discard_job` | `job_id`, optional `include_preview` | Cancel preparation, discard a proposal or restore current affected live targets. |

## Explicit reads

Discover the intended font once with `list_documents`; retain its `document_id`
for this MCP connection and reuse it for fresh reads of the same font. Rediscover
after `document_not_found` or explicit target change, never for an unrelated
input error. Never substitute another open font. Reconsider current/frontmost
intent when the prior target may no longer be intended.

`entities` is a list of selectors. `fields` applies to each requested entity, so group compatible entity kinds in a call.

| Kind | Selector | Available fields |
| --- | --- | --- |
| Glyph | `{"kind":"glyph","id":"H"}` | `name`, `unicode`, `category`, `subCategory`, `export` |
| Layer | `{"kind":"layer","glyph":"H","id":"<layer ID>"}` | `id`, `name`, `width`, `vertWidth`, `vertOrigin`, `leftMetricsKey`, `rightMetricsKey`, `widthMetricsKey`, `bounds`, `outlineHash` |
| Master | `{"kind":"master","id":"<master ID>"}` | `id`, `name` |
| Master page | `{"kind":"masters","limit":100}`; sole selector | `id`, `name`; see pagination below |
| Context | `{"kind":"context"}`; optional `glyphLimit` with `selectedGlyphs` | `view`, `master`, `selectedGlyphs` |
| Selection | `{"kind":"selection"}`; optional `nodeLimit` only with `nodes` | `glyph`, `layer`, `selectedNodeCount`, `selectedAnchorCount`, `selectedComponentCount`, `selectedGuideCount`, `selectedOtherCount`, optional `nodes` |
| Kerning | `{"kind":"kerning","master":"<master ID>","direction":"LTR","left":"A","right":"V"}` | `value` only; `null` means absent. |

Resolve IDs from the document or selection data; do not guess a layer ID. Kerning selectors address stored keys. Supported directions are `LTR`, `RTL` and `vertical`; collision preparation is LTR only.

`layer.read.exact.v1` in `get_status.bridge.readCapabilities` advertises exact
layer selection and native `id = layerId` read-back. Supply both a nonempty glyph
name and exact native layer ID; omitted/wrong-type values return `invalid_request`,
and missing targets or name aliases return `target_not_found`. Special/backup
layers can be read by their own explicit IDs; their names are not selectors.
If a required capability is unavailable, the private installation needs updating:
update the bridge, sidecar and skills together, reload and verify fresh status.
Do not substitute workflows for earlier private builds. Stored layer metrics keys and optional vertical
values do not resolve glyph-level inheritance. Native bounds preserve fractions;
`outlineHash` is an opaque guard, not a geometry payload. See the shipped
`glyphs/references/layer-reads.md` for field limits and measurement interpretation.

For master discovery, require `masters.list.v1` in `get_status` → `bridge.readCapabilities`.
The page's `values.items` contains native IDs/names, `total` gives the current count,
and `complete: false` requires another call with `nextCursor` passed unchanged as
the selector's `cursor`. The integer limit is 1–100. A page cannot be mixed with
other selectors. Reads work on dirty and unsaved documents without saving.
`stale_master_cursor` requires restarting without a cursor after a document,
count or page-boundary change. Pages are live reads, not an atomic snapshot;
avoid editing between pages and re-enumerate after observed edits.

`master.read.exact.v1` advertises strict explicit master selection: require a
nonempty native ID, never a name alias. IDs need not be UUIDs, and names can repeat.
Require these capabilities on the current private build; if absent, update the
bridge, sidecar and skills together. Protocol 1 alone does not establish support.

For document context, require negotiated `document.context.v1`. Use one context
selector and request `view`, `master` and/or `selectedGlyphs`. View is `font`,
`edit` or `unavailable`; master is native id/name or null. Selected glyph names
follow native `font.selection` or `font.selectedLayers` order, bounded by an
integer `glyphLimit` of 1–100 (default 100). Native selection can collapse repeated
Edit View occurrences. `total`, `returned`, `limit`, `complete` and `source` make
coverage explicit; missing native evidence includes an `unavailable` reason.
Incomplete evidence is not a complete edit scope. No node details are implicit.
See `glyphs/references/context-reads.md`. This capability also advertises the
native `isCurrent` marker in `list_documents`; retained IDs never retarget.

For selection, require negotiated `selection.context.v1`. Request the compact
counts explicitly; smaller projections remain valid. Add `nodes` only when
coordinates are needed, with one selection entity in the entire request.
`nodeLimit` defaults to 64 and accepts integers 1–256. Nodes return `total`,
`returned`, `limit`, `complete` and `items`; truncated evidence is never complete.
Indices use zero-based `layer.paths` (excluding components) and `path.nodes`
(including off-curves). Null glyph/layer and `nodes:null` mean no active Edit View.
See the shipped `glyphs/references/selection-reads.md` for exact semantics.

Stored kerning reads use exactly `fields:["value"]` and 1–100 explicit selectors.
Use glyph names or established stored `@MMK_` group keys, not native glyph IDs.
`null` means no entry for the exact keys/master/direction; zero is stored and
fractions are retained. This does not compute effective class/exception kerning.
Dirty and unsaved fonts need no Save or job for inspection. One bad selector
rejects the request. See `glyphs/references/kerning-reads.md` for recovery.

Example `read_entities` arguments:

```json
{
  "document_id": "<document ID>",
  "entities": [{"kind": "selection"}],
  "fields": ["glyph", "layer", "selectedNodeCount"]
}
```

## Supported job kinds

| `kind` | Scope and options |
| --- | --- |
| `width_delta` | Finite, nonzero `delta`; optional `glyphs`; no `options`. Adjusts widths across the selected glyphs' layers. |
| `spacing` | Optional glyphs and master IDs, references, width mode and sampling options. [Spacing guide](../spacing-tools.md). |
| `kerning_collision` | Explicit `options.pairs`, optional master IDs and sampling options; no `glyphs`. [Kerning guide](../kerning-workflow.md). |
| `start_nodes` | Explicit glyphs, contour index and master/reference selection. [Correspondence guide](../workflows/start-node-correspondence.mdx). |
| `slant` | Optional glyphs, angle, pivot, master IDs and straight-stem preservation. [Slant guide](../italic-first-pass.md). |

Only `width_delta` accepts `delta`. The other jobs use `options`. A supplied `glyphs` list must contain unique nonempty names; use the workflow's narrower limits where specified. Missing or incompatible targets are reported, not silently substituted.

## Results and lifecycle

Tool results use the existing envelope: `{"ok":true,"data":...}` or `{"ok":false,"error":...}`. Inspect the returned data rather than treating transport success as job success.

A job starts as `preparing`, then becomes `ready`, `failed` or moves through `cancelling` to `cancelled`. Applying a ready job moves through `applying` to its reported outcome. Discarding an applied job moves through `discarding`. Use `get_job` until the operation is terminal; inspect errors and recovery details even when preparation initially succeeded.

`include_preview` defaults to `true` on `get_job`, `apply_job` and `discard_job`. Set it to `false` to omit top-level `sample` and `report.sample`; the response explicitly returns `previewIncluded:false`. Counts, report metadata, progress, errors and operation state remain. Read the full report once before application and use the compact projection for subsequent polling.

`get_job` includes a compact sample and, where supplied, the path to the full external report. One glyph can produce several changes. A ready proposal with no changes is not evidence that a new spacing result was applied.

Both preparation and application require a saved, clean baseline. Save accepts the reviewed result; native Undo/Redo use per-glyph history. Discard restores the entire job only where its affected targets remain current. See [Safety and recovery](../concepts/safety-model.mdx).

For uncertain execution, retain the job ID and reconcile it with `get_job`. Do not automatically submit a replacement. Job IDs belong to the current service session, not a durable cross-restart queue.

## Precision and boundaries

Spacing preparation and reference comparison use an inclusive absolute **0.001 font-unit** tolerance. Width changes are evaluated independently of negligible translations. Native write verification, recovery, Undo/Redo, topology and source hashes remain exact.

There are no additional v2 MCP endpoints for arbitrary Python, export, master replacement, Unicode assignment or general font repair. Those tasks use native Glyphs operations or reviewed workspace scripts. The companions add native views, not extra MCP tools.
