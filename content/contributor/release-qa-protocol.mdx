---
title: V2 release validation
---

Validate the lean candidate without modifying the original font. Preserve the workspace and prior acceptance evidence before assembling an isolated candidate.

## Automated checks

Run the complete Python and installer suites, focused companion and lifecycle regressions, documentation and skill checks, module budgets, deterministic unsigned builds and `git diff --check`. Qualify private runtime startup offline on both supported architectures.

Cover dispatch/timeout ordering, competing and repeated operations, partial native setters, failed readback/recovery, cancellation/publication orderings and native fractional-coordinate Undo/Redo. Exact history and recovery checks must not use display tolerance.

## Native acceptance

Install the verified bundles and restart Glyphs safely. Run three consecutive disposable-font acceptance cycles covering spacing, fractional widths and coordinates, cancellation/recovery, native Undo/Redo and companion startup/redraw. Compare saved data with an untouched native-save control and verify the original source hash.

Check the menu reference indicators, active-layer-only status text, the shared welcome placeholder and heart button. Confirm first-launch persistence without repeated automatic presentation. Retain the reports and source-hash evidence.

Record idle and loaded responsiveness separately. A 200 ms HTTP probe is diagnostic rather than an automatic rejection; investigate reproducible stalls attributable to the plugin and distinguish modal waiting from native execution.

## Packaging and identity

Validate component combinations, upgrades, removal, interrupted installation and complete transactional rollback. Verify preservation of unrelated files and user preferences. Sign nested code from the inside out, notarize and staple, then reverify exact payload identities and the installed receipt.

Record which checks were run on unsigned, signed and final notarized artifacts. Documentation-only updates do not retroactively change the source manifest or acceptance report belonging to an already signed installer.

Follow the repository's `macos-installer/RELEASING.md` for local release commands. Public publication is separate from local acceptance.
