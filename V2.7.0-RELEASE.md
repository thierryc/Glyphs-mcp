# Glyphs MCP 2.7.0 / build 91

Stable release for Glyphs 4. [Download the notarized disk image](https://github.com/thierryc/Glyphs-mcp/releases/download/v2.7.0/Glyphs-MCP-2.7.0.dmg)

## Changes since 2.6.0

- Setup groups document counts and memory readings, each with its own
  timestamp. Copy the Markdown report from Setup or the macOS menu bar.
- Glyphs responsiveness and macOS memory pressure are reported separately.
  The card and Markdown report show the Glyphs footprint as a share of installed
  RAM. Light and moderate footprints use green, heavy footprints use orange,
  and critical Mac pressure or a severe response delay uses red. Elevated
  pressure gives agents guidance specific to their work.
- Dashboard sections share one title style, page spacing, and a soft blur as
  content scrolls behind the header on macOS 26. The header fades to pure white
  in light mode. Setup opens directly on the server status.
- The menu bar dropdown shows three dot indicators for MCP connection,
  Glyphs 4 and the Glyphs footprint.
- The Tasks list sits closer to the sidebar and title bar.
- Tasks distinguish recorded outcomes from current recovery decisions and show
  remaining work. Stopped-script reservations are released only after terminal
  bridge evidence confirms that writes and recovery are no longer pending.
- The desktop has a narrower project sidebar and a Notes-style header with
  softer control shadows on macOS 26. The top-right MCP status opens Setup.
- The companion, bridge, sidecar and four agent manifests use 2.7.0. The lean
  interface and bridge protocol stay at revision 1, with 22 tools and 14
  managed skills. Glyphs 3 uses the separate pinned 1.11.0 distribution.

## Native and VM acceptance

The signed 2.6.0/build 76 → 2.7.0/build 91 update passed in a disposable
VirtualBuddy macOS 26.6.2 arm64 guest. Sparkle rejected an invalid feed signature,
an interrupted download and an invalid archive signature. The valid private
signed feed delivered the exact release ZIP. Install and Relaunch replaced the
app with the exact signed build 91 bundle and left the build 76 component
receipt byte for byte intact.

The bundled production installer migrated the three signed components. The
running bridge and sidecar matched the build 91 receipt, all 22 tools were
visible, and the port, onboarding preference and guest data fixture were
preserved. A repeat installation while Glyphs was open refused before changes
and preserved the receipt and plug-in signatures. The live Health card showed
separate observation timestamps and RAM share. The three-dot menu and both
Markdown copy actions passed.

Detached Glyphs 4.2/build 4203 passed native edits and discards on a disposable
256-glyph font, saved-source integrity, controlled critical pressure and recovery
hysteresis. Over 12 measured rounds, median prepare-plus-apply time was 251.28 ms
on build 76 and 251.62 ms on build 91. Median native callback time was 56.36 ms
and 55.75 ms respectively. Build 91 also passed Run, Cancel and Restore on
disposable Glyphs and Glyphs package fixtures, preserving earlier unsaved
edits and saved source bytes.

The remaining live checks ran in the `Glyphs-November` VM on macOS 26.6.2
arm64 with Glyphs 4.1.1/build 4108 and official Glyphs Python 3.14.6. The exact
signed build 91 opened and listed a disposable font through the receipt-matched
bridge and sidecar. Cancelling the installer’s quit request kept the same
Glyphs process and unsaved edits, and preserved the fixture source and receipt.
MCP stayed stopped after cancellation. **Start Server** in Setup restored the
connection to the same edited document.

A controlled receipt replacement failure during an in-place build 91 reinstall
occurred after six other replacements. The production installer restored all
seven original destinations and the running sidecar. The three plug-in
signatures, original receipt and native connection passed verification after
rollback. The signed upgrade used a private feed. All six public release downloads matched the verified local files before
the signed stable feed advanced. [Public download verification](reports/release-2.7.0/public-downloads.json) Physical Intel execution is optional for 2.7.0 and remains unverified. The local evidence is recorded in
`dist/2.7.0-build91-acceptance.json`.
