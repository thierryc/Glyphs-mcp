## Implemented behavior

- Distinguish a crash from a timeout, stopped bridge or dirty font; check process existence before UI tools can relaunch it.
- Retain uncertain job IDs. After an authorized restart, refresh identity and rediscover the exact document without replaying an interrupted patch.
- Offer a pause only for a plausible periodic-autosave trigger, with explicit consent for the incident, exact application, disposable test and a maximum of five minutes.
- Explain the app-wide loss of periodic crash recovery and that restoration is manual. Declined or unanswered means no pause; general testing/installation approval is insufficient.
- Read and record the native delay before changing it. Restore that exact value on completion, error, cancellation or deadline, then verify it in the same process. Unverified restoration stops the affected work.
- No persistent defaults, replacement Undo, document-retention workaround, watchdog, automatic restart or invented Python MCP tool.

The native option is documented by a [Glyphs maintainer](https://forum.glyphsapp.com/t/glyphs-3-3-3316-suddenly-crashing/31415) and [Apple](https://developer.apple.com/documentation/appkit/nsdocumentcontroller/autosavingdelay). It remains an untested mitigation for this particular Glyphs 4 crash. No pause, native font edit, restart or external developer contact occurred in this follow-up.
