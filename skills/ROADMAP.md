# Glyphs MCP v2 skill roadmap

## Goal

Skills are the expertise layer of Glyphs MCP v2. They assemble font-design and
Glyphs work from pinned Knowledge, generic reads, explicit constraints,
immutable previews, verified writes, proofing, and a permanent Python fallback.
They do not depend on domain workflow endpoints.

## Required workflow

Every managed skill follows the same sequence where applicable:

1. Search `search_knowledge` when a factual, version-specific, API, format, or
   font-engineering claim is needed; retrieve exact entries with
   `get_knowledge`.
2. Read current document evidence with `list_documents` and `read_document`.
3. Apply the skill's expertise: calculations, references, exceptions,
   typographic judgment, and proof design.
4. Use `evaluate_constraints` for reusable assertions.
5. When expressible, create an exact `preview_change`, inspect its resolved
   identities, semantic diff, quantization, constraint evidence, warnings, and
   blockers, then apply that immutable patch with `apply_change`.
6. When generic mechanics are insufficient, use permanent `execute_python`:
   `read_only` for inspection, `staged_document` for detached structural work,
   and `live_open_world` only for unsupported APIs or external effects.
7. Re-read and verify the result. Never save unless the user separately asks
   for `save_document`.

Staged Python is applied through `apply_change` and is never rerun. Live Python
must distinguish verified document effects from unverifiable external effects
and report checkpoints or recovery evidence.

## Authorship and packaging

- `skills/` is the only authored source.
- `plugins/glyphs-mcp/skills/` is generated by
  `scripts/sync_codex_plugin_skills.sh`.
- Each skill stays focused and progressive: workflow in `SKILL.md`, deep facts
  in Knowledge, and only task-specific supporting references in the skill.
- No skill may reference a retired v2 tool.
- Python fallback criteria must be explicit in every domain skill.

Validate changes with:

```bash
scripts/sync_codex_plugin_skills.sh
scripts/sync_codex_plugin_skills.sh --check
python3.12 -m pytest -q src/glyphs-mcp/tests/test_v2_skill_contracts.py
```

## Milestones

### 0. Architecture freeze — complete

Knowledge → Skills → Tools ownership, the 18-tool public contract, hard-reset
removal policy, permanent Python fallback, and authored/generated boundaries
are fixed.

### 1. Generic evidence — complete

Selectors, projections, relations, provenance, completeness, observations, and
fingerprint-bound pagination replace collection-specific read workflows.

### 2. Verified changes — complete

Constraints, immutable previews, exact stored patch apply, rollback, audit,
history, and conflict-aware revert share one transaction kernel.

### 3. Spacing reference — complete

Spacing uses axis-neutral projections plus explicit `set` and `translate`
operations. Arithmetic, reference choice, exceptions, negative-sidebearing
judgment, and proof strategy live in the spacing skill and Knowledge.

### 4. Permanent Python — complete

Read-only, detached staged, and live open-world modes are first-class. Staged
changes share the generic preview/apply lifecycle; live effects retain honest
recovery semantics.

### 5. Pinned Knowledge — complete

The deterministic offline corpus covers type design, font engineering, Glyphs
coding, APIs, and formats with stable IDs, citations, versions, dates, and
checksums.

### 6. Skill cutover — complete

All managed skills use the common sequence above, packaged mirrors are
generated, and retired workflow solvers are absent.

### 7. Qualification — maintained continuously

Schema, selector, projection, constraints, preview/apply equivalence, semantic
patch inversion, pagination, Knowledge, Python, bundle determinism, routing,
and disposable Glyphs 4 gates must remain green for release.
