**Report 01 candidate test specification**

Compare installed Beta 1 code with the separate candidate from the Beta 1 release checkout. Product labels remain 2.0.0 Beta 1, build 43; distinguish builds by their component fingerprints. Do not install, restart the installed endpoint, change v1 settings, or create font jobs.

1. Preserve installed sidecar, bridge, v1, skill files, receipt and app metadata. Read the configured entry before selecting a matching control. Snapshot catalogs and skill checksums.
2. Build the complete candidate payload twice, compare every file, compile and verify an unsigned desktop application. Validate release stamping, deterministic fingerprints, changed-file detection, initialization-time stability, unavailable evidence and receipt propagation. Signing-byte changes are simulated in tests; no release is signed or published.
3. Run baseline then candidate in independent, plugin-free Glyphs 4 workers with fresh job directories and tokens. Use free loopback ports, leaving 9680 and 9681 untouched. Do not open fonts. Check identity on every status request and the exact catalog in every timed trial.
4. Record first connection, one warm-up and five measured fresh sessions: initialize, catalog, status. Use a separate session for 20 status requests spaced by 50 ms and two document-preservation reads. Retain the first failed harness attempt, pilot pair, uninstrumented controls and final verified pair separately.
5. Temporarily wrap the existing scheduling callback and status calls inside the harness only. Measure enqueue-to-Cocoa-callback delay, callback execution, bridge HTTP duration, and service duration minus bridge HTTP duration (sidecar assembly). No disk writes occur inside these measured intervals; flush timing data at shutdown. The synthetic worker run loop pumps at 10 ms, while the bridge retains its native 2 ms scheduling yield.
6. Compute median, min/max and nearest-rank p95. The 50 ms p95 / 200 ms maximum reference applies to measured isolated callback responsiveness; public request latency is a separate proxy. No mutation occurs, so the two seconds after mutation check is inapplicable. Unchanged identifiers and hashes require exact equality; no geometry tolerance is involved.
7. Check candidate routing against captured v1, live lean, legacy 0.1.0, missing skills, unknown interfaces and two independent connection inputs. Record this as single-agent instruction review, distinct from automated text contracts and live MCP execution. No hidden operation or custom router completes unsupported work.
8. Report configured-skill failure even if the matching control succeeds. Test installer ownership, unchanged installs, managed upgrades, preserved edits, unowned conflicts and explicit replacement backups in temporary homes. Preserve the existing invocation policy.

The final pair uses Python 3.14.7, FastMCP 2.12.0, MCP SDK 1.29.1 and glyphs-cli 0.6.1 for both implementations. Report 01 originally used MCP SDK 1.12.4, negotiating 2025-06-18. The follow-up negotiates 2025-11-25 for both builds; this is a client negotiation difference, not a changed bridge/interface protocol. Cold startup includes normal client initialization; server process startup is outside the connection timing. Record load rather than claiming an idle machine.
