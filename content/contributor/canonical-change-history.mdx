# Canonical change history

Glyphs MCP 2.0 records each document-scoped MCP tool call as an immutable action
commit. This borrows Git's useful data model—content-addressed objects, parented
commits, a working-tree head, semantic diffs, and conflict-aware revert—without
running Git or treating an unsaved Glyphs document as a filesystem repository.

The history has one lifetime: the current unsaved editing session. A successful
normal save clears that document's commits, overlay reference, and unreachable
objects. Saving a copy or a failed save does not clear it. Long-term comparison
against a saved file, Time Machine, or a repository commit is a separate future
adapter that can feed the same canonical tree and diff engine.

## One source, two independent projections

The **Glyphs MCP Change Log** is a passive tool-call ledger. It lists command,
result, timestamp, changed glyphs or document roots, and semantic before/after
values. Selecting a row changes only the panel text. It never opens a tab,
changes a master or selection, activates a Reporter, or modifies editor state.

The **Glyphs MCP Changes** Reporter is a drawing-only Edit View projection of
the latest contiguous agent session. It reads a cached net semantic diff rather
than the selected Change Log row. The applied Glyphs outline stays normal; the
pre-agent outline is the fixed baseline and the current native layer is the
live comparison. The Reporter fills only the warm translucent geometric band
between those two shapes; it never traces or recolors the complete outline. If
the user moves another node afterward, the band updates on the next Glyphs
redraw to include that movement relative to the same baseline. Reverting the
layer to the baseline naturally leaves no visible band.

Topology-compatible paths are paired exactly by path, segment, and node order.
If later editing changes that topology, the Reporter draws no approximate band;
the complete semantic change remains available in the Change Log.

Both views are projections of the same operation and `CanonicalFontTree`
data, but neither owns or drives the other.

## CanonicalFontTree storage

The native adapter first detaches Glyphs objects into JSON-safe canonical data
on the main thread. Everything after that boundary operates on plain Python
values away from Glyphs UI objects.

Snapshots use SHA-256 content addressing. Glyph and kerning roots are sharded;
each glyph is stored independently, then referenced by a small map object and a
font-tree root. A one-glyph edit therefore reuses every unchanged glyph object
instead of copying the complete font for every tool call. Identical values are
inserted once.

The live runtime uses a thread-safe in-memory object store because history is
ephemeral until save. This avoids filesystem traffic while Glyphs is editing.
A private compressed SQLite backend exists for tests and future persistence;
it uses a single short batch per snapshot, `0700` parent permissions, and a
`0600` database.

The tree descriptor carries two independent versions. `schemaVersion` describes
the content-addressed storage layout. `modelSchemaVersion` describes the
semantic font projection. They must never be treated as interchangeable. The
descriptor also declares `reversibilityCoverage: modeled_fields_only` because
the canonical model does not claim to contain every private Glyphs or PyObjC
field. A model fingerprint is therefore an exact identity for that versioned
projection, not a byte-for-byte identity for an arbitrary native document.

Model schema v4 keeps ordered collections as plain detached JSON lists while
addressing masters, instances, features, classes, and prefixes by stable entity
ID. Membership and scalar patches are independent from a minimal `$order`
patch, so create/delete/update/reorder, selective revert, storage, and audit all
share one semantic representation. Glyph membership uses the same whole-entity
principle on its name-keyed map. Master-owned layer membership is one bounded
layer-entity change per glyph, and a duplicated master's kerning is one atomic
partition; ordinary kerning batches remain one semantic change per pair.

Master lifecycle replay also carries a small process-local execution context
that identifies the native copy source. It is not font data and is never stored
in the canonical tree, public diff, or audit ledger. When a master is removed,
the adapter retains native copies of that master and its owned layers only for
the unsaved operation lifetime. This preserves custom parameters, guides,
hints, backgrounds, and other native fields that model schema v4 does not yet
project. The tombstone is released after verified revert or successful save.

The live adapter carries the same model as an immutable `CanonicalSnapshot`.
Its exact schema-v4 document fingerprint is cached separately from an internal
content-tree hash. Root, glyph, and layer references are retained while native
revision evidence agrees; a verified transition replaces only shards named by
its semantic paths. A stable repeat capture therefore neither deep-copies nor
rehashes the complete font.

`CanonicalImpact` is derived from semantic paths rather than tool names.
Master order and italic/axis changes touch no glyph shards. A master rename
checks the corresponding layer-name fragment. Duplicate and delete check one
owned layer entity per glyph plus the master and kerning partition. The native
verifier streams authoritative sibling values against the expected snapshot;
an unexpected out-of-impact value forces materialization of the real mismatch
and can never inherit the expected fingerprint.

Canonical fields have explicit roles:

- **writable source fields** can participate in an automatic semantic replay;
- **derived fields** such as compatibility verdicts are observed and verified
  but are never assigned as if they were source data;
- **read-only modeled fields** support analysis but not write-back;
- **unmodeled native fields** are outside automatic rollback coverage.

Adding a field, changing identity rules, or moving a field between these roles
requires a model-schema revision plus clone, serialization, and live-host gates.
Open-world Python remains recovery-only whenever its complete native effect is
not proven representable by the current model.

Verified typed transactions retain the requested writable patch, the complete
clone-observed semantic diff, the intended canonical target, and a small replay
strategy. Reconciliation first uses identity-preserving native edits on a
detached copy. It recaptures that copy and compares it with the intended tree.
If a changed canonical collection still differs, the remaining tree diff—not
the tool name or mutation type—selects deterministic replacement for that
collection. The same detached copy must then reproduce the target exactly; a
second clone is not created for reconciliation. The selected strategy is reused
once in the live transaction and verified by read-back. No metrics-, spacing-,
or glyph-specific rollback rule participates in this decision.

Initial capture, clone, detached apply, verification, live apply, settled
verification, history, and total timings are retained only as bounded internal
diagnostics. The schema-v4 live gate includes them in its explicit result, but
ordinary MCP responses and the capability manifest do not expose profiling
fields.

History, pagination, and the Reporter use the observed diff. The latest-session
diff is cached when operations are recorded, so Reporter redraws perform only
affected-glyph and affected-layer lookups plus one detached capture of the layer
currently being drawn. Reporter callbacks never hash or capture the full font,
write, prune, or mutate a Glyphs object.

## Revert semantics

`list_change_commits` exposes bounded operation summaries. `get_operation`
accepts the same operation ID returned by the mutation to page through its
semantic diff. `revert_change` takes that operation ID and creates another
verified operation; it does not delete or rewrite history.

Revert checks every changed path against the value originally written by the
commit. Unrelated later edits are preserved. If any affected path was changed
afterward, the revert fails with explicit conflicts and applies nothing. The
rebased inverse is an intended canonical tree, not a sequence of inverse
setters. The result still uses detached reconciliation plus the shared one-shot
main-thread transaction, read-back, verification, rollback-on-failure, and audit
kernel. If the current model cannot be reconciled exactly, the operation is
refused before the live document is touched.
Each active MCP mutation owns one native change-count contribution. A verified
selective revert removes its corresponding contribution regardless of order;
native user history is never globally cleared.

## Performance and safety gates

- A 383-glyph, five-master one-glyph edit reuses 382 glyph objects and inserts
  no more than four new content objects.
- A detached 1,000-glyph, five-master snapshot must complete within the bounded
  scale test without touching native Glyphs objects.
- Repeated Reporter reads reuse the cached session diff and perform no full-tree
  diff.
- The Change Log has no polling timer and refreshes only from history or document
  lifecycle callbacks.
- Closing a document removes only its process-local history. Saving clears only
  the exact saved document.
- The explicit Glyphs 4 schema-v3 qualification gate composes the public typed
  tools and `revert_change`; it owns no mutation or rollback implementation of
  its own. It must restore the exact disposable baseline after normal and
  injected-failure paths before reporting success.
- Files, subprocesses, network effects, preferences, and other open-world side
  effects are never represented as reversible document commits.

This architecture deliberately does not implement branch, merge, or rebase UI.
Those operations can be built later over the same immutable objects after their
font-specific conflict rules are specified and tested.
