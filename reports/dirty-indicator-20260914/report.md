# Dirty-indicator investigation — September 14, 2026

**The dirty indicator has multiple causes. Two are actionable in v2’s existing native grouping hooks; a further Redo count drift also reproduces through the ordinary Glyphs UI. No product fix was installed during this investigation.**

This is a separate follow-up to P09–P13. The HTTP route correction, fractional-node restoration and historical autosave crashes are separate issues. Previous measurements and v1 remain unchanged.

## Measured primary results

Numbers below are the native `control.changeCount`. “Clean” means `isDocumentEdited() == false`, not a visual guess from the window’s close button.

| Workflow | Fresh trials | Edit | First Undo | Redo | Final Undo | Data restoration |
|---|---:|---:|---:|---:|---:|---|
| Native width field | 2 | 1 / dirty | 0 / clean | 2 / dirty | 1 / dirty | Width, geometry, metadata, object identities and hint links restore; native glyph `lastChange` remains updated |
| Installed v2 width job | 2 | 1 / dirty | 1 / dirty | 3 / dirty | 2 / dirty | All captured data, including `lastChange`, objects, bounds and hint links restore exactly |
| Installed v2 apply→discard | 1 clean control | 1 / dirty | — | — | 2 / dirty after discard | All captured data, objects, bounds and hint links restore exactly |

The native width-field result reproduced both before and after an ordinary autosave. The native dirty flag clears on the first Undo after autosaving, although `hasUnautosavedChanges` may be true because the autosaved copy differs. Conversely, v2 can report dirty=true while `hasUnautosavedChanges=false`. These flags answer different questions.

For the two v2 trials, the native glyph manager still had grouping level 1 after application. It reached level 0 when Undo ran. The ordinary UI edits were already at level 0. No pending width-field editor remained in the primary trials; focus was returned to the canvas before Undo.

Additional controls:

- After a v2 edit to `control`, a native UI edit changed only `unrelated` from 700 to 708. Public discard restored `control` to 600 and preserved the unrelated width, metadata, timestamp and native objects exactly. Its glyph Undo still worked. Dirty=true was required while that unrelated edit remained.
- Preparing a new job on an initially dirty font returned `document_not_clean`. Exact before/after data, object and hint-reference comparisons passed. Ordinary Undo subsequently restored its width and cleared the dirty flag.
- The original open font remained clean with exact captured data and object preservation. No user font was edited or saved.

The existing oracle was extended to retain glyph `lastChange`. Therefore native UI restoration is **not** labelled fully exact: the timestamp difference is recorded rather than filtered out. The full comparison is in [facts.json](facts.json), generated by [analyze.py](analyze.py).

## Isolated cause checks

These native diagnostic probes use fresh copies inside the same Glyphs process. They call existing native APIs and a separately copied `write_value` with read-only stage logging. Installed bridge functions and native methods were not patched. Explicit native-manager calls are not UI test results.

| Probe | Observed result | Implication |
|---|---|---|
| Toggle temporary rounding suppression on/off | Clean, count 0, exact captured data | This flag alone does not cause the tested dirty state |
| Open/close document group through current `NativeUndoScope` | Dirty, glyph count 0, exact captured data | An unused document group can dirty the document independently of glyph data |
| Open/close document group without setting an action name | Same dirty result after settling | Omitting the group name alone is insufficient |
| Native width setter with an explicit group while automatic grouping is enabled | First Undo restores width but leaves count 1 | The extra group interaction also occurs without v2’s inverse block |
| Copied v2 registration, glyph group only | First Undo leaves count 1 | Removing the document group alone does not fix glyph bookkeeping |
| Copied registration plus document group | Same glyph drift, plus document history | Reproduces both independent contributors |
| Native setter without an explicit extra group | First Undo clean; Redo→Undo leaves count 1 | Matches both primary UI trials |
| Copied registration in one explicit glyph group, automatic grouping temporarily disabled and restored | First Undo clean with exact captured restoration; Redo→Undo still leaves count 1 | A bounded change to existing group handling is promising, but not a complete fix |

The document-group result occurred three times across two named-group probes and the unnamed-group control. The first isolation attempt stopped because the harness incorrectly required grouping level 0 before native `undo()`. Glyphs still had a level-1 automatic group. That failed attempt is retained; the revised diagnostic allowed levels 0 or 1 and let the native method handle the group. It did not forcibly close history or alter counters.

Stage logs show that the extra count appears **before** the restoration callback: the pre-Undo observation has count 1 and grouping level 1; callback entry has count 2; Undo returns with count 1 and grouping level 0. The single-group control eliminates that extra increment, supporting pending outer-group closure as the cause. The internal native implementation was not traced. The logged inverse registration, temporary registration suppression and exact setter leave the count unchanged within that callback. This locates the first-Undo discrepancy at the interaction between explicit and automatic native groups, rather than at coordinate writes.

For Redo, the single-group control moves from count 0 to 2 and then to 1 on Undo. The ordinary UI and native-setter control reproduce the same sequence. That establishes a native-path reproduction in this installation, **not exclusive attribution to Glyphs core**: the usual plugins were loaded, and no clean plugin-free GUI profile or second host build was tested. Reference Inspector was the active reporter; the bridge and other plugins were installed. No developer was contacted.

Whole-job discard uses reverse writes through the same existing hooks, not a rewind of every native history. Its count increase is consistent with that implementation. Clearing a global dirty flag would conceal unrelated edits and is not an acceptable correction.

Evidence: [first isolation attempt](isolated-bookkeeping-first.json), [main stage traces](isolated-bookkeeping-primary-probes.json), [single-group and native controls](isolated-bookkeeping.json), [unaltered source copy](native-undo-source.py), [logged copy](native-undo-instrumented.py).

## Recommended lean follow-up

1. **Make the fallback document manager lazy.** In existing `NativeUndoScope`, include it only when an operation actually uses it. Keep font/group kerning cases covered; `manager_for(None)` currently selects the fallback. Preserve per-glyph grouping and current target inverses.
2. **Qualify one owned native group per touched manager.** The diagnostic that temporarily disables automatic grouping, opens/closes one explicit group and restores the original setting clears first-Undo dirtiness. Implement only after testing pre-existing groups, multiple glyphs/masters, chunk boundaries, cancellation and exceptions. Never close somebody else’s group or clear native counters. Restore the setting on every exit. No new history, snapshot, watcher or recovery system is needed.
3. **Keep native Redo and discard semantics explicit.** The above changes cannot yet promise a clean indicator after Redo→Undo or whole-job discard. Reproduce Redo in a plugin-free Glyphs 4 test environment and another available build before assigning it exclusively to the host. Keep actual data restoration separate from the native dirty flag. Do not compensate by decrementing counters or forcing clean state.

Acceptance for a candidate: exact data/object/hint/metadata restoration; clean initial apply→Undo; preserved unrelated dirty edits/history; stable native group levels and settings; existing jobs, cancellation, Redo and discard behavior; seven unchanged tools; normal autosaving and crash observation. Redo/discard dirty-state failures must remain visible unless separately resolved. The single-group probe is feasibility evidence, not release qualification. No product code or skill edit was made here.

## Documentation and limits

Apple documents edited state and unautosaved state separately, and explains that default NSDocument Undo notifications update change bookkeeping. That supports reading these values separately; it does not promise correctness for a host’s custom glyph manager. See [NSDocument updateChangeCount](https://developer.apple.com/documentation/appkit/nsdocument/updatechangecount(_:)) and the installed AppKit/Glyphs header locations in [sources.md](sources.md).

The [Glyphs forum discussion about the edited dot](https://forum.glyphsapp.com/t/close-icon-does-not-show-dot-on-edited-file/32577) describes autosave/Versions-dependent UI behavior in Glyphs 3; it is not evidence of this Glyphs 4 Undo defect. A [separate Undo discussion](https://forum.glyphsapp.com/t/undo-has-suddenly-stopped-working-properly/35637) reports a different symptom involving a plugin. It reinforces the need for plugin isolation before exclusive attribution, not a diagnosis of our case.

There is no evidence from these trials that pausing autosave is needed for the dirty indicator. No new Glyphs crash report appeared; PID 16388 survived. This does not resolve the historical autosave crash or the independent fractional-node restoration issue.
