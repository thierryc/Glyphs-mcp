---
title: Settings and preferences
---

Use **Edit → Glyphs MCP Server…** for application-wide server controls, even with no font open.

| Setting or control | Behavior |
| --- | --- |
| Start / Stop | Controls the external MCP server. Active preparation, writes, cancellation or recovery prevent shutdown. The native bridge remains available for a later restart. |
| MCP port | The client port defaults to 9680. **Apply Port** validates the port and restarts a running server. Use **Copy URL** to update your client afterward. |
| Copy URL | Copies the configured endpoint, including the `/mcp/` path. The button becomes available when the panel has confirmed the configuration. |
| Automatic start | Starts the external server at the next login. |
| Open Logs | Opens diagnostic information. |
| Heart button | Opens or focuses Glyphs' nonmodal Welcome/support links panel. |

The default local MCP URL is `http://127.0.0.1:9680/mcp/`. The **Glyphs MCP Bridge** palette reports the state of the internal connection between the server and Glyphs.

Product versions and interface/protocol revisions have different meanings. Use `get_status` to verify the installed component versions and fingerprints. See [version and identity](version-identity.mdx).

Server preferences are application-wide. Comparison references are stored per saved font path. A native checkmark and filename/revision identify the current reference in **Edit → Comparison Reference**; the complete values are in its tooltip.

Glyphs' Welcome/support panel appears automatically once after a successful first display. Closing it does not disable the heart button. It is nonmodal and shared across documents, and can be opened without a font.

Upgrades preserve ports, startup choices, authentication and welcome preferences. Component and connector installation, updates and removals are managed on Setup. Use the discreet Setup log button for paths, per-card failures and redacted diagnostics.

Legacy v1 environment-variable controls are documented in the [v1 settings guide](/docs/reference/settings). They are not the v2 configuration contract.

The local v2 desktop introduction has its own first-launch completion
preference. Replay its six slides through **File → Welcome & Support** or the
sidebar; Skip/Start setup opens Setup. Completed relaunches and quiet login
startup do not automatically reopen it.

Desktop Settings also controls menu-bar visibility, optional desktop launch at
login and automatic update checks, which are enabled by default and can be disabled. Desktop login startup is independent of the sidecar service. See [desktop behavior](../getting-started/desktop.mdx).
