# Glyphs MCP 2.5.0 — historical local preparation

The final published release is **2.5.0/build 73**. See [release qualification](V2.5.0-RELEASE.md). The build-72 notes below retain their preparation scope.

Source target: **2.5.0/build 72**, stable channel, unreleased. The app, bridge
and four agent manifests have been advanced locally; the sidecar derives its
product identity through the existing release helper. Published **2.4.0/build

was installed and reloaded under explicit authorization. This preparation now
has a fresh verified unsigned local 2.5.0 app; it has not installed or published
that candidate.

## Included scope

| Change | Result |
| --- | --- |
| Live Path Doctor diagnosis | Inspect unsaved live paths; distinguish definite defects, suspicious structures and valid drawing conventions; report precise addresses, evidence, repair holds and scan coverage. |
| Qualified closed-seam repair | Remove only the redundant zero-length closure while preserving real segments, editable geometry, stroke order, profiles and inherited defaults. Reuse preparation, selective recovery and native Undo. |
| Pen-point cleanup guidance | Establish profile correspondence before simplifying; protect meaningful controls and assess cumulative worst-case error across masters and native intermediate instances. Use the existing recoverable script workflow for explicitly requested custom edits. |
| Catalogue delivery | Existing apps discover and download the self-contained, licensed Path Doctor package after Refresh, using an immutable commit and archive checksum. |
| Transition to inclusion | The next app prefers its own reviewed included canonical payload over the official download; unrelated name collisions still fail. |
| Codex identity | Advertise the existing Glyphs MCP logo and product website through server/proxy initialization, with readable workflow tool titles and invocation labels. |
| Codex setup | Reuse matching plugin connections and discover desktop-bundled CLIs. Preserve custom/disabled/conflicting settings and edits made during discovery; direct plugin-owned removal to Codex settings. |
| Activity feedback | Report measured callback counts or indeterminate whole-script activity, finishing phases and partial failures, without changing execution, cancellation or recovery semantics. |
| Compact cards | Show light/dark progress and necessary controls in a small card, retaining detailed evidence behind Details and keeping warnings/recovery consequences visible. |

## Recorded evidence and limits

The earlier installed implementation passed 141 focused checks in the full
checkout and a clean export of the accepted scope. The latest skill/catalogue
extension passed 67 focused Python tests and 25 native catalogue tests; the
independent catalogue passed its six tests and public CI. A native download
check used the installed app's real snapshot and legacy merge policy. Refresh
then visibly showed Glyphs Path Doctor as Installed. These checks cover their
recorded implementation, not newly signed 2.5.0 artifacts.

The local 2.5.0 identity preparation passed 85 focused versioning, release,
Path Doctor and skill/package checks, plus synchronization, coordinated-identity
and lean-package validation. These source checks do not replace the complete
release gate or exact-artifact acceptance below.

Native seam repair is qualified on Glyphs **4.2 (4202)** for foreground ordinary
masters. Other builds remain diagnostic-only until qualified. Conflicting
profiles, locks, references and unsupported structures are held. Native Save
can reduce coordinate precision; exact in-memory repair does not promise
lossless arbitrary live-coordinate persistence.

Pen-point cleanup is a guided, measured workflow, not a blanket automatic
redistribution command. Small profile changes require explicit authorization
and a reported error budget. A mismatched designspace needs its correspondence
correction reported separately from later simplification error. Fill,
smoothness, direction and intentional returns remain independent. OpenPlotFont
converter changes belong in its owning repository and are not included here.

Private fonts, profile measurements, drawings and disposable files stay local
and ignored. Public regressions are original generic examples. Our two open
test documents were closed; owner fonts were not saved for cleanup.

## Codex integration accepted into this scope

The owner subsequently requested completion and inclusion of the Codex work.
It is now part of the 2.5.0 source candidate:

- Codex connection detection/configuration preservation and bundled CLI discovery.
- Server identity/icon presentation and request-scoped activity notifications.
- Compact workflow progress cards and their localisation, tests and documentation.

Review added explicit refusal for conflicting effective connections and a fresh
configuration check after asynchronous CLI discovery. New regressions cover
those cases, request cancellation without replaying native execution, and
fractional/invalid progress counters. The completed full Python run passed
3,327 tests with four skips, and the full native desktop suite passed 325 tests.
A separate run of all 23 feedback tests against the pinned runtime passed
without skips, covering its newer SDK's icon fields. The isolated Codex
0.165.0-alpha.1.2 app-server checks passed for
standalone, plugin-only and overlapping registrations using the locked runtime;
they verify icon bytes, plugin attribution, the 22-tool contract and progress
projection without touching the user's Codex configuration or any font.

Browser inspection covered light/dark cards, whole-script activity, measured
callbacks and narrow partial-failure/recovery states. Standard progress
notifications work with the MCP client; the tested Codex direct-call endpoint
does not forward them. Exact icon placement remains host-dependent. The card
and ordinary structured workflow state provide progress independently.
