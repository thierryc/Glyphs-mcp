# Glyphs MCP 2.4.0 — release preparation

Source target: **2.4.0/build 71**, stable channel, prepared 27 October 2026.
Planned tag: `v2.4.0`. This version is not published.
The published baseline remains **2.3.1/build 69**, with its signed feed,
tags and distribution assets preserved.

## Changes

- Retain typed-export instance selection after native recovery regenerates live
  IDs. Verify the complete ordered instance collection and immutable source
  before resolving a unique saved slot; reject drift or ambiguity without
  saving or rewriting the font. Include both identities in the export report.
- Show creation dates in task rows and start, last-activity and expiry dates in details.
- Add **Settings → Tasks → Expire inactive tasks after**, default **1 day**,
  with 7-, 30- and 90-day choices. Close abandoned intent as Expired while
  preserving unknown/partial outcomes and diagnostics. Protect active work and
  usable recovery; cancel only unapplied previews. Stop overdue queued intent
  before it can execute. Preference changes apply without a server restart.
- Simplify Tasks into **Needs attention**, **Active** and **Finished**.
  Distinguish Working from Waiting, and show outcomes separately from recovery.
- Let independent fonts continue while another document retains script recovery,
  including after confirmed stopped partial execution. Keep same-document
  recovery decisions and protections for active execution, cleanup and unknown
  outcomes.
- Explain each blocker with its owning task, affected font, resource scope and
  whether it clears automatically or requires a decision. Add **View blocking
  task** to the native Tasks window.
- Accept busy requests as **Waiting** and resume them automatically without
  closing unrelated recovery. Preserve document order and preview authorization;
  keep intake, inspection and cancellation responsive during native calls.
- Present existing modified or unowned skills as successfully preserved
  information under **Configured**, with a positive setup summary. Real
  configuration errors retain their failure state.
- Preserve live recovery records during operation pruning. Stop advertising
  cached memory recovery after a known bridge restart or lost operation.
- Keep partial failures and incomplete typed recovery visible for inspection.
  Fold associated preparation and prerequisite-save steps into their request.
- Allow staged exports to publish independently of live font work. Show export
  destination conflicts in Tasks and keep them retryable with a new destination.
- Update English, French and Simplified Chinese interface copy and synchronize
  the shared agent-package guidance.

## Release identity and compatibility

Desktop, bridge, sidecar and all four host plugin manifests target **2.4.0**.
The app build is **71**. The stable channel has beta number **0**.
The catalog remains **22 tools** (21 data/action tools and one optional display
tool), **12 managed skills**, interface revision **1** and bridge protocol **1**.
Internal Python distribution versions and independently versioned companions
retain their existing identities. The pinned Glyphs 3 release remains 1.11.0.

The additive `tasks.document-recovery.v1` capability negotiates document-scoped
recovery with the bridge. Older bridges retain their existing protections.
The sidecar's additive `edit.queue.automatic.v1` capability advertises queue
intake and automatic resumption. The queue is bounded to 128 waiting requests;
unknown writes and interrupted requests are never automatically replayed.
Existing tool inputs, workflow identities, idempotency and action-token checks
remain in place. Finished presentation does not close recovery or save a font.

Planned distribution names are `Glyphs-MCP-2.4.0.dmg` and
`Glyphs-MCP-2.4.0.zip`, with the normal stable aliases prepared only by the
release pipeline. The published `appcast.xml` remains on 2.3.1 until final
artifact verification and publication.

## Build 71: dates and configurable expiry

The new unsigned candidate adds creation dates to task rows and creation,
last-activity and expiry times to details. Settings → Tasks defaults to **1 day**,
with 7-, 30- and 90-day choices. Its atomic shared preference is read by background
maintenance without a server restart. Polling and startup do not renew old
authorization. Overdue queued intent cannot execute when Glyphs becomes ready.

Expiry retains diagnostics, errors, receipts and action history. It never
chooses Keep, Save, Undo or Restore. A native idle/ownership check protects
available recovery, real execution and uncertain native ownership; only an
unapplied preview can be cancelled during expiry. Missing local job metadata
does not bypass native recovery checks. Accepted cancellation retains its
normal cleanup instead of turning into an expired request.

Qualification passed **1,963 runtime tests** (one skip), **312 desktop tests**,
**193 final regression checks**, and **15 isolated native Glyphs checks**. The
native checks confirmed that old unapplied previews expire without font edits,
100-day-old available snapshots stay intact and remain restorable, and preference
changes take effect without restarting. Documentation, package, managed-skill
synchronization and whitespace checks passed.

The build-71 unsigned candidate was rebuilt separately. The installed build-70
manager, bridge and sidecar and their live task records were not changed.
Build-71 evidence is in `output/task-expiry-build71-20261027/`. Signing,
notarization and publication remain stopped.
