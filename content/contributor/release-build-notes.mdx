Build, sign and notarize locally on the maintainer’s Mac. GitHub Actions deploys documentation, not release artifacts. The source tag records the exact build inputs; reuse sealed artifacts and accepted receipts when those inputs are unchanged.

The installer manifest and receipt describe the runtime, bridge and companions independently, with dependencies and verified identities. Signing changes file identities; regenerate and verify manifests after signing and stapling, before packaging the final installer. Unsigned/local checks alone do not establish Developer ID, notarization or signed-update acceptance. Record those results for the exact final artifacts.

## Stable deliverables

- `Glyphs-MCP-2.0.2.dmg`: signed and notarized installer.
- `Glyphs-MCP-2.0.2.zip`: Sparkle-signed desktop application archive.
- `Glyphs-MCP-latest.dmg`: byte-identical alias of the verified stable DMG. The compatibility `Glyphs.MCP.zip` and `SHA256SUMS` complete the inventory.
- `appcast.xml`: the signed stable feed, published unchanged after public archive verification.
- Checksums cover the exact release inventory; source and acceptance receipts identify the qualified build.

Keep local acceptance evidence containing private font paths out of public release assets unless reviewed for sharing. Store notarization credentials in Keychain.

## Discoverable releases

The desktop uses checksum-pinned Sparkle and PierreDiffsSwift packages. Build
receipts verify the Pierre package resource bundle and the exact bundled
`@pierre/diffs` and Shiki JavaScript identities. **Check for Updates** runs on
demand; automatic checking is enabled by default and can be disabled in Settings. The 2.0.2 release uses the stable feed
`https://raw.githubusercontent.com/thierryc/Glyphs-mcp/main/appcast.xml`
and archives under its signed `v2.0.2` tag. The preserved Beta feed stays separate
at `lit/v2-beta/appcast.xml`. Sparkle update ordering uses increasing installer
builds, not the marketing-version label. A configured feed is not proof that
it is publicly available.

The local publishing scripts verify source refs, signatures, checksums and uploaded asset identities before publication, then verify the exact release by tag. A beta must be a prerelease with `make_latest=false`; confirm that the stable Latest release is unchanged. A local build or a draft is not a public release. Publish only as a separately authorized step and update the documentation's candidate status and `/latest` destination accordingly.

See [Release validation](release-qa-protocol.mdx) and [documentation maintenance](local-docs-development.mdx).

## Local desktop build

Run `scripts/build_desktop_release.sh` with the verified Python build environment. It prepares checksum-pinned Sparkle, builds and signs the app and nested components, notarizes and staples, creates the DMG, and creates `dist/desktop-update/` with the signed archive, feed candidate and checksums. It never publishes.

The Sparkle signing key stays in Keychain under account `cx.ap.glyphsMcp`, separate from the Developer ID certificate. Never export it into the repository. Application updates are separate from component migrations; acceptance must exercise a signed older-to-newer app update and component rollback.

Published 2.0.1 added Open, Import, Activate and Close under the
matching `document.*.v1` capabilities, bringing the public tool count to seventeen.
`create_document` remains available under `document.create.v1`. See the current
command reference for explicit unsaved handling, retry safety and separate Save As.
