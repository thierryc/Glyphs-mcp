---
title: Safety and recovery
---

A prepared job is a proposal. Applying it changes the open font but does not save it. The designer reviews the result in Glyphs and uses native Save to accept it.

## Baseline and ownership

Preparation requires a saved, clean font. Before application, the sidecar checks the document path, edit generation and source hash. The bridge also checks affected targets before writing. An external edit or a stale source rejects the operation instead of silently overwriting it.

Apply, discard and rollback share one per-document exclusion mechanism. Ownership is reserved before opening native Undo scopes and released on terminal or failed-start paths. Use a disposable copy for broad experiments.

## Native Undo, Redo and discard

Native Undo and Redo operate in each affected glyph's history, including fractional widths and grouped coordinates. Native rounding flags and Undo registration are restored after each exact operation. `discard_job` restores the entire job's still-current affected targets, subject to conflict checks.

A conflict means a target has changed outside the operation. Discard does not overwrite that target to force a clean-looking result. Review the error, preserve subsequent edits and decide whether native history or Revert is appropriate.

## Partial failures and timeouts

Before a native write, the bridge records the target's exact starting state. If a setter partially fails, it restores that current target before yielding, then reverses earlier writes through chunked rollback. Recovery is verified. An incomplete restoration is reported explicitly inside the existing error details.

A main-thread callback can be pending, running, completed or cancelled. A timeout cancels a pending callback so it cannot run later. If execution has started, the outcome is **uncertain** until reconciled. Keep the job ID and call `get_job`; do not automatically submit a replacement or claim no changes occurred.

## Cancellation

`discard_job` requests cancellation during preparation or reversal during live application. Cancellation and publication share the service lock: cancellation that wins prevents a later `ready` result; if publication wins first, discard handles the ready proposal normally. Temporary artifacts are released only after the worker stops using them; the terminal job record is retained for the session.

Do not restart the sidecar to cancel or reconcile an operation. Job sessions do not continue across server restarts.

## Precision policy

Spacing preparation and reference comparison treat absolute differences **at or below 0.001 font units** as insignificant. A skipped translation does not suppress an independently meaningful width change.

This tolerance does not apply to native write verification, source hashes, topology, restoration or Undo/Redo. Those checks remain exact. Meaningful changes that a native setter cannot store exactly are reported as unavailable or failed rather than rounded into a different result.
