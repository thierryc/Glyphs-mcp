---
title: Release QA protocol
description: Manual release test protocol for validating Glyphs MCP against Glyphs 3.5 and Glyphs 4 on a large real font.
---

This protocol is the pre-release manual QA pass for Glyphs MCP. Run it before publishing a new public version, especially after changes to the plug-in bundle, command registration, Glyphs API compatibility, installer, tool profiles, tool schemas, or mutation helpers.

The goal is not to prove every implementation branch. Unit tests do that. The goal is to verify that the most common real workflows still work in realistic conditions: a large production `.glyphs` file, real Glyphs UI state, a real MCP client, the Streamable HTTP endpoint, and both supported app lines.

## Release gate

A release is ready only when all required checks pass in both:

| Runtime | Required result |
| --- | --- |
| Glyphs 3.5.x | All required checks pass or have documented, accepted Glyphs-3-only limitations. |
| Glyphs 4.x | All required checks pass or have documented, accepted Glyphs-4-only limitations. |

Release blockers:

- A selected Glyphs target's Python environment is not checked before any
  dependency, plug-in, or client change.
- An incompatible existing native extension is reported as an installation
  success, or the diagnostic omits the exact Python or offending file.
- Server cannot start, restart, or stop from **Edit -> Glyphs MCP Server**.
- Client cannot connect to `http://127.0.0.1:9680/mcp/`.
- `get_server_info`, `list_open_fonts`, or `get_selected_font_and_master` fails in normal use.
- The advertised version, code hash, runtime ID, tool profile, or resource path is clearly wrong.
- A read-only tool mutates the font.
- A mutation tool changes the font without `confirm=true` when it is expected to be confirm-gated.
- A dry run mutates the font.
- A common workflow crashes Glyphs, hangs the server, corrupts the font, or returns unbounded output.
- Glyphs 3.5 and Glyphs 4 expose materially different tool schemas without a documented compatibility reason.

## Automated per-tool release gate

Every public MCP tool must have an entry in `src/glyphs-mcp/tests/test_release_gate_tool_coverage.py`.

That gate records:

- The test owner or accepted live-smoke requirement.
- Whether the tool is read-only, edits the font, runs code, writes files, opens UI, saves files, or exposes server docs.
- The undo-risk level.
- A short live smoke prompt that can be reused in Glyphs 3.5 and Glyphs 4.

The automated gate must pass before any release candidate:

```bash
python3 -m unittest src/glyphs-mcp/tests/test_release_gate_tool_coverage.py
python3 -m unittest discover -s src/glyphs-mcp/tests
```

Release blockers from this gate:

- A registered MCP tool is missing from the release-gate manifest.
- A stale manifest entry names a tool that is no longer registered.
- A tool entry has no owner test, no live smoke prompt, or no undo-risk classification.
- An editing or code-execution tool is not classified for undo risk.
- Any executable Python resource calls `glyph.beginUndo()` or `glyph.endUndo()`.

The last rule is intentional. Live Glyphs 4 QA showed that MCP-driven batch edits can trigger Glyphs' "There was a problem with undo" recovery dialog when glyph undo groups are used around larger script edits. Mutation helpers should use documented layer/font update APIs and small scoped writes instead.

## Test assets

Use at least one large real font file. A good release candidate font has:

- 1,000+ glyphs.
- 2+ masters, ideally with roman and italic or weight/width variation.
- Multiple instances.
- Real kerning groups and several thousand kerning pairs.
- OpenType features, including at least one `ssXX` feature.
- Components, anchors, annotations if available, guides, bracket layers if available, and non-exporting glyphs.
- A mix of simple and complex outlines.

Never run destructive tests on the only copy of a production file.

Prepare these files:

| File | Purpose |
| --- | --- |
| `LargeFont-release-baseline.glyphs` | Untouched reference copy. |
| `LargeFont-release-glyphs35.glyphs` | Glyphs 3.5 working copy. |
| `LargeFont-release-glyphs4.glyphs` | Glyphs 4 working copy. |

For each working copy, record:

- File path.
- File size.
- Glyph count.
- Master count and master names.
- Instance count.
- Kerning pair count for the main master.
- Glyphs app version and build number.
- Glyphs MCP version being tested.
- Git commit or release tag.

## Preflight

For each app version:

1. Quit all Glyphs versions.
2. Run the release installer once with a compatible environment. Confirm
   **Check Python environment** names the exact selected interpreter and the
   matching Glyphs 3 or Glyphs 4 `Scripts/site-packages` path.
3. Install the release candidate plug-in and dependencies using the same path
   users will use: signed installer app or terminal **Copy** mode. Test
   development **Link** mode separately when relevant, and label it as outside
   the signed-release guarantee. Do not use a raw manual source copy as a
   release-path test.
4. Start only the app version under test.
5. Open the matching large-font working copy.
6. Start the server from **Edit -> Glyphs MCP Server**.
7. Confirm the status panel shows the expected version, profile, endpoint, and docs URL.
8. Connect the MCP client to:

```text
http://127.0.0.1:9680/mcp/
```

9. Reconnect the MCP client after every profile change.
10. Keep the Macro Panel visible during at least one pass and capture any repeated tracebacks.

Pass criteria:

- Server starts without traceback.
- Port `9680` is reachable locally.
- Browser access to `/mcp/` returns discovery JSON or an expected MCP transport response.
- MCP client can list tools.
- The large font remains open and responsive.

## Installer ABI diagnostic matrix

Run this matrix before the normal live workflow in both Glyphs 3.5 and Glyphs
4. Use disposable package fixtures; never alter the only copy of a shared
environment.

| Case | Fixture | Required result |
| --- | --- | --- |
| ABI-1 | Empty or partially missing dependencies | Preflight is non-blocking and pip begins. |
| ABI-2 | Python 3.14 with only `cpython-311` `pydantic_core` and `objc` extensions | Preflight fails with the exact interpreter, ABI, and files. No persistent change occurs. |
| ABI-3 | Matching CPython extensions | Preflight passes. |
| ABI-4 | Compatible `.abi3` extension | Preflight passes. |
| ABI-5 | Compatible universal Mach-O extension | Preflight passes. |
| ABI-6 | Mixed stale and compatible files where the compatible module imports | Preflight passes; stale alternatives alone do not block. |
| ABI-7 | Wrong-architecture or broken existing package | Preflight fails deterministically before pip. |
| ABI-8 | Post-install missing import, nonzero exit, malformed JSON, timeout, unexpected origin, or stderr-only output | Installation never reaches success. |

For ABI-2 and ABI-7, compare filesystem snapshots from before and after the
attempt. The target `Scripts/site-packages`, installed plug-in, and client
configuration must be unchanged. Save the full JSON-derived installer log.
Repeat the boundary in terminal interactive and non-interactive modes and
confirm status `2`.

## Transport and schema checks

Run once in each required matrix case before workflow testing.

| ID | Action | Expected result |
| --- | --- | --- |
| T1 | Connect a real MCP client to `/mcp/` using Streamable HTTP. | Client initializes without transport warnings. |
| T2 | Inspect request/response headers if the client exposes them. | Session handling is stable; any returned `Mcp-Session-Id` is preserved by the client. |
| T3 | Call `tools/list` or use the client's tool inventory view. | Tool names, descriptions, and schemas load without JSON schema errors. |
| T4 | Compare `tools/list` in `Read-only` and `Edit` profiles. | `Read-only` hides mutation and execution tools; `Edit` exposes the full surface. |
| T5 | Compare the observed `Edit` profile tool list with the current [command set](../reference/command-set.mdx). | Missing, renamed, or extra tools are intentional and documented. |
| T6 | Call one tool with malformed JSON arguments. | Error is structured and bounded; server remains usable. |
| T7 | Call one tool with a valid but semantically invalid argument, such as a bad `font_index`. | Error clearly identifies the invalid input. |

## Smoke tests

Run first in every matrix case.

| ID | Action | Expected result |
| --- | --- | --- |
| S1 | Call `get_server_info`. | Returns version, runtime ID, code hash, resource path, Glyphs reachability, open-font count, and no error. |
| S2 | Call `list_open_fonts`. | Shows the large font with a stable `font_index`, family name, file path if saved, and expected glyph/master counts. |
| S3 | Call `get_font_masters` for the large font. | Returns all masters with stable IDs, names, metrics, and no missing active master. |
| S4 | Call `get_font_instances`. | Returns instances without crashing on interpolation data. |
| S5 | Select 3-8 glyphs in Glyphs, then call `get_selected_font_and_master`. | Response matches the active font, active master, and current UI selection. |
| S6 | Switch the active master in Glyphs and repeat S5. | Active master changes in the response. |
| S7 | Stop and restart the server from Glyphs UI, then reconnect. | New calls succeed; stale client sessions fail gracefully or reconnect cleanly. |
| S8 | Switch between `Read-only` and `Edit` profiles, reconnecting each time. | `tools/list` changes as expected; hidden mutation tools are unavailable in `Read-only`. |

| R3 | Call `get_glyph_components` for composite glyphs. | Component names, transforms, and target layers are understandable. |
| R4 | Call `get_glyph_paths` for simple and complex glyphs. | Returns valid path JSON and bounded output. |
| R5 | Select nodes in Glyphs and call `get_selected_nodes`. | Reports selected nodes with layer, path, node index, and per-master mapping when available. |
| R6 | Call `get_selected_glyphs` after changing selection in Glyphs. | Response tracks the UI selection and includes show links where possible. |
| R7 | Call `list_style_sets`. | Returns stylistic sets, source/replacement glyph groups, and group show links for alternates. |
| R8 | Call `get_font_kerning` for the main master. | Returns kerning data without timeout, broken group names, or excessive client-side truncation. |
| R9 | Call `review_collinear_handles` on one glyph with curves. | Returns findings or a clean result without mutation. |
| R10 | Call `render_glyph_review_image` for 6-12 glyphs with metrics, sidebearings, bounds, nodes, handles, anchors, and guides overlays. | Client receives a visible image or base64 fallback; Glyphs does not become dirty. |
| R11 | Click or open a returned `showHttpUrl` or `showMarkdown` link. | Glyphs focuses the expected glyph/layer, or the response explains why the link is unavailable. |

## Curve geometry workflow

Run review cases in both profiles. Run confirmed mutation only in `Edit` on a
disposable glyph or working copy. Record the explicit path and segment end-node
indices so the Glyphs 3.5 and Glyphs 4 results can be compared.

| ID | Action | Expected result |
| --- | --- | --- |
| CG1 | Call `review_tunni_geometry` for one curved glyph/master/path, then repeat with one unsuitable explicit index. | Returns bounded ratios, eligibility, proposals, and stable rejected records with `eligible:false` and a reason code, without changing document state. |
| CG2 | Call `review_curve_quality` for the same path with `include_samples=false`. | Returns bounded curvature metrics, exact maximum/median spike semantics, JSON-safe zero-median markers, component omissions, and warnings without an artistic pass/fail verdict or mutation. |
| CG3 | Call `set_curve_review_overlay(enabled=true)`, inspect a correctly wound outer contour and counter plus reversed equivalent paths in **View > Show Glyphs MCP Curvature**, then call `get_curve_review_overlay_state`. | Live teal-positive/pink-negative teeth and connected envelope runs are visible; outer combs point into non-ink outside the shape, counter combs point into the white counter, and reversal preserves tooth lengths while reversing placement and signed color; native sampling is 51 per cubic with a `0.010` scale and `0.12em` normal clamp; last-draw glyph/layer, stroke, hard-clamp/cap, and component-omission data are bounded; the font remains clean. Toggle off and confirm the drawing disappears. |
| CG4 | Call `apply_tunni_balance` with `dry_run=true` for one explicit eligible segment. | Proposed handle coordinates match review; node and document signatures remain byte-for-byte unchanged. |
| CG5 | After approval, call the same target with `confirm=true` on the disposable glyph. | The applied record contains actual verified before/after coordinates, exactly its two reported handles move, topology/types/smooth flags remain stable, verification succeeds, and no save occurs. |
| CG6 | Exercise controlled write, read-back, and `endChanges()` failures against a disposable fixture. | Every original coordinate is restored, rollback succeeds, and begin/end change calls are attempted as a paired batch. |

## Hybrid candidate review workflow

Run HCR1-HCR8 in both Glyphs 3.5 and Glyphs 4 using serialized disposable
copies under `/private/tmp`. Run preview/review in both profiles; materialize,
accept, and discard only in Edit. Record source and candidate fingerprints.

| ID | Action | Expected result |
| --- | --- | --- |
| HCR1 | Preview grid-safe Tunni targets in every master and switch active masters. Capture at least one frame whose measured outline displacement is visibly large. | **View > Show Glyphs MCP Candidate** activates automatically; localized warm-yellow difference ribbons contain real non-background pixels over the untouched Glyphs outline, without dirtying the font. The Reporter reports `differenceCompositor="appkit_topology_paired_contour_ribbons"`; identical geometry draws no glyph-area overlay. A successful draw counter without visible difference pixels is a failure. |
| HCR2 | Change one source handle after preview. | The recomputed difference turns coral red with `STALE`; review blocks with `stale_source` and issues no token. |
| HCR3 | Materialize the session after a successful dry run. | Complete copies receive new layer IDs, source-master associations, plain names, direct links, and namespaced manifests; backgrounds remain untouched and partial failure rolls back all copies. |
| HCR4 | Make one operation-permitted manual edit, rename the candidate, and re-review with diffs. | Cosmetic rename is ignored; exact bounded deltas are reported and a five-minute fingerprint-bound token is issued. |
| HCR5 | Try topology, protected metadata, unrelated node, off-grid, or operation-external edits. | Review blocks with stable reasons and no token. |
| HCR6 | Dry-run then confirm acceptance with the exact token. | Only approved fields move, every read-back verifies, candidates/manifests are removed after success, required italic/tuning backups remain, and no save occurs. |
| HCR7 | Change source or candidate after review, reuse a consumed token, and exercise write/read-back/cleanup/end-change failures. | Tokens fail closed; complete source/candidate/manifest/backup state is restored on any transactional failure. |
| HCR8 | Materialize, restart the plug-in, re-review, then discard a second session. | Materialized state recovers from metadata; discard deletes only owned candidates; ephemeral previews disappear on restart and can be regenerated. |

Pass criteria:

- Read-only profile exposes both review tools but not `apply_tunni_balance`.
- Read-only and Edit expose both native Reporter control tools.
- Glyphs 3.5 path order and Glyphs 4 path order within mixed shapes identify
  equivalent paths and segment end-node indices.
- Invalid, parallel, short-handle, distant-intersection, out-of-ratio, and
  excessive-movement cases return stable reasons rather than mutating.
- Boolean, fractional, and numeric-string segment indices are rejected. NaN
  and infinite numeric thresholds are rejected before target mutation.
- A change made after dispatch but before main-thread execution is observed by
  the confirmed recomputation; a stale proposal is never written.
- Confirmed apply triggers no undo recovery dialog and never saves the font.

This acceptance record is intentionally scoped to path behavior in Glyphs 3.5.
Component omission and mixed path/component ordering remain covered by the

### Glyphs 3.5 build 3530 disposable-fixture safety

Two attempts to broaden the live Glyphs 3.5 fixture exposed host behavior that
was separate from MCP tool execution:

- Constructing a synthetic mixed-component font reached Glyphs private
  `_lastComponentOperation` / `needsAlignment` code and crashed the host.
- Opening a visible serialized temporary fixture caused an AppKit autosave hang
  and created a separate `CurveQA (Autosaved).glyphs` file. The source-copy
  hash remained exact.

For build 3530 curve-failure injection, prefer an untitled, in-memory,
path-only disposable fixture. Do not synthesize mixed components in the live
interpreter or open a serialized visible temporary fixture solely to expand
CG1-CG6 unless that fixture path has been vetted separately. Use the automated
component/mixed-shape coverage and the live Glyphs 4 pass for those cases. The
two temporary files and their directory from this pass were deleted; no
repository or user font was saved.

## Cross-version comparison

After the two required app passes, compare the result logs.

Record differences in:

- Tool list and schemas.
- Server info fields.
- Font, master, instance, glyph, path, component, and kerning response shapes.
- Show-link availability.
- Image rendering output.
- Error messages.
- Performance.
- Dirty-state behavior.
- Any Glyphs API compatibility warning in the Macro Panel.

Acceptable differences:

- Glyphs app build numbers.
- Glyphs API fields that do not exist in one app version.
- Different internal layer/master IDs for files resaved by different app versions.
- Minor rendering differences that do not block visual review.

Unacceptable differences:

- Same tool call succeeds in one app version and crashes or hangs in the other.
- Mutating calls affect different targets.
- Dry runs mutate in either app.
- Tool schemas are missing in one app version without intentional profile or compatibility reason.
