# Release QA protocol

Run this protocol only after the complete local release gate passes. The 2.0
installer intentionally ships two different runtimes:

- Glyphs 3.5 -> pinned v1.11 from signed baseline `v1.11.0` / `13ca805`.
- Glyphs 4 -> v2.0 from the deterministic generated bundle.

Catalog equality is not an acceptance criterion. Each host must match its own
declared runtime track, version, safety contract, and payload manifest.

## Automated prerequisite

From the repository root, run:

```bash
python3 scripts/bump_version.py --dry-run --installer-build 27 2.0.0
PYTHON_BIN=python3.12 ./scripts/run_local_release_tests.sh
```

The consolidated gate runs shell and patch checks, the complete Python matrix,
two byte-identical schema-v2 payload builds, source/package skill parity,
canonical and packaged skill validation, the documentation production build,
the complete Xcode suite, an unsigned Debug app build, and unsigned-candidate
metadata validation. It also verifies pinned format hashes, generates the
schema-v6 coverage report, requires zero unclassified official paths, and runs
the independent flat/package source-seam audit. With
`GLYPHS_MCP_FULL_NETWORK=1`, upstream knowledge drift blocks qualification. It
does not sign, notarize, install, tag, upload, or publish anything.

## Containment and evidence

- Use only `Glyphs MCP V2 Disposable - Gee gee.glyphspackage` for Glyphs 4
  mutation gates. Never open or save the production Gee gee source.
- Record the disposable package tree hash, working path, canonical fingerprint,
  native archive fingerprint, dirty state, and active master before each gate.
- A Glyphs 3.5 check is read-only and must not mutate a document.
- Every Glyphs 4 gate must restore its exact canonical and native baseline,
  working path, dirty state, and active master before the next gate starts.
- Run heavyweight gates separately. Return control to Glyphs between phases
  and expose progress through the Glyphs MCP inspector; do not run one opaque,
  monolithic qualification task.
- No live installation is replaced by this protocol. Installer behavior is
  exercised only against simulated target roots.
- Treat a development symlink and its generated target as one effective live
  installation. Rebuilding the target changes the code Glyphs will load even
  when the symlink itself is unchanged.
- Before either host matrix, verify that the resolved plug-in bundle already
  has the required host version. Stop rather than qualifying a `dev` build as a
  release or rebuilding a protected link target implicitly.

## Glyphs 3.5 pinned-runtime matrix

Record Glyphs build, Python version, plug-in path, resolved link target, runtime
version, and catalog counts.

| ID | Action | Required result |
| --- | --- | --- |
| G3-1 | Launch Glyphs 3.5 with the pinned development link. | Runtime is exactly `1.11.0`; no v2 module is loaded. |
| G3-2 | Start, stop, and restart the MCP server, reconnecting a fresh client each time. | No duplicate server, stale event loop, or reconnect failure. |
| G3-3 | Call server info, open-font listing, and one bounded read-only font/glyph query. | Results match the v1.11 contract; document and file state remain unchanged. |
| G3-4 | Inspect update state. | Glyphs 3 is pinned; no v2 notification, stage, or authorization can replace it. |
| G3-5 | Stop the server and close any disposable document without saving. | Plug-in link and source bytes remain unchanged. |

Do not run v2 canonical mutations, staged Python, Change Log, or rollback gates
on Glyphs 3.5. Those APIs do not belong to its pinned runtime.

## Glyphs 4 v2 runtime matrix

Record Glyphs build, Python version, generated plug-in hash, runtime version,
catalog size, discovery payload size, and selected disposable document ID.

### Runtime and transport

| ID | Action | Required result |
| --- | --- | --- |
| G4-1 | Start, stop, restart, and reconnect the server. | Every client receives v2.0 identity and the exact v2 catalog. |
| G4-2 | Inspect complete discovery. | Payload is below 96 KiB; removed preparation and Candidate APIs are absent. |
| G4-3 | Run bounded document, glyph, layer, master, instance, feature, pair/context kerning, and change-log reads. Exercise `entryKind=pair`, `context`, and `all`, plus `context_sequences` coverage. | Every response page is below 64 KiB, directions remain distinct, raw contexts remain visible, filtered cursors cannot cross scopes, and no read performs a mutation. |
| G4-4 | Leave one connection idle, cancel one bounded call, then reconnect. | No per-second debug-ping flood, progressive slowdown, or poisoned server state. |

### Verified apply-first kernel

Run existing gates independently; do not reproduce their mutation logic in the
release protocol.

| ID | Existing gate | Required result |
| --- | --- | --- |
| G4-5 | `verify_schema_v3_structural_kernel` | Glyph, OpenType, instance, selective-revert, and atomic-refusal domains pass; exact baseline restored. |
| G4-6 | `verify_schema_v4_master_lifecycle` | Master duplicate/update/move/delete and reverse-order revert pass in at most 72 seconds. |
| G4-7 | `verify_schema_v5_layer_lifecycle` | Intermediate, alternate, backup, Smart, and color layer lifecycle passes with unrelated shard reuse. |
| G4-8 | `verify_staged_python_structural_replay` | Preview and confirmation cover glyph, master, layer, instance, feature, class, and prefix lifecycle without rerunning Python. |
| G4-9 | `verify_copy_and_make_copy` | `save(path, makeCopy=True)` leaves the working path and dirty state unchanged. |
| G4-10 | `verify_context_kerning` | Both `L quoteright A` boundaries apply atomically through native context deltas, list/read back exactly, preserve all pair domains, refuse a two-glyph context, and restore the exact canonical/native baseline without saving. |

Each successful mutation and revert must report one live transaction, one
canonical operation ID, one Change Log commit, and one audit receipt. Failed
apply, verification, rollback, stale, or conflict cases must restore their
exact pre-attempt content and dirty contribution.

### Change feedback and visual state

| ID | Action | Required result |
| --- | --- | --- |
| G4-11 | Apply a topology-compatible outline change. | Change Log lists its semantic targets and the Reporter shows the geometric before/current gap. |
| G4-12 | Move one affected point manually. | Overlay updates against the fixed pre-agent baseline without full-font capture during drawing. |
| G4-13 | Revert the operation exactly. | Overlay disappears and Change Log status updates; baseline and dirty state are exact. |
| G4-14 | Revert an earlier operation while an unrelated later operation remains. | Later change is preserved; a conflicting later edit refuses atomically. |
| G4-15 | Open and collapse the Glyphs MCP inspector during a long phase. | Compact activity feedback remains document-bound and the UI returns between gates. |

### Exported contextual-kerning proof

After G4-10 restores its baseline, make a separate disposable proof update for
both `L’A` boundaries. Use illustrative values only if they are visibly
appropriate for the disposable design.

| ID | Action | Required result |
| --- | --- | --- |
| G4-16 | Compare `L’A` with `L’O`, `l’A`, standalone `’A`, and an unrelated apostrophe–`A` occurrence in Glyphs Context Kerning mode and normal Kerning & Spacing mode. | Only the complete positive context receives the extra boundary values; ordinary pair views remain unchanged. |
| G4-17 | Export to a temporary destination and test Text Preview/CoreText plus one external shaping environment with `kern` on and off. | With `kern` on, both contextual deltas are additional to pair kerning; controls remain unchanged. With `kern` off, ordinary and contextual kerning disappear. |
| G4-18 | For variable output, inspect named instances and intermediate slider positions; otherwise inspect every relevant static instance. | Interpolation is continuous and no master-specific context is missing. |

Remove the temporary export, revert the proof operation, and re-confirm the
canonical/native baseline. Do not record this gate as passed from stored-value
readback alone.

## Simulated installer matrix

Use temporary Glyphs Application Support roots. Do not target the live plug-in
folders or alter the existing development symlinks.

| ID | Action | Required result |
| --- | --- | --- |
| I-1 | Build the payload twice. | Complete file maps are byte-for-byte equal. |
| I-2 | Inspect `payload.json`. | Schema 2 maps Glyphs 3 to `1.11.0`/`1.x`/`pinned` and Glyphs 4 to `2.0.0`/`2.x`/`release`. |
| I-3 | Install and reinstall Glyphs 3 in a simulated root. | Glyphs 4 target remains byte-identical. |
| I-4 | Install and reinstall Glyphs 4 in a simulated root. | Glyphs 3 target remains byte-identical. |
| I-5 | Inject a replacement failure for either host. | That host restores its prior bundle; the other host is untouched. |
| I-6 | Uninstall either host. | Other host, shared dependencies, skills, documents, and unrelated preferences remain. |
| I-7 | Present protocol-v1 update state. | It cannot satisfy or authorize a protocol-v2 request. |
| I-8 | Enable then remove the Glyphs 3 update pin. | Only installer-owned preference values are restored, and only while unchanged. |
| I-9 | Start from development symlinks. | They remain unless replacement was explicitly selected. |

## Qualification record

Record results in `release-build-notes.mdx` only after they were actually run:

```md
- Candidate: 2.0.0 (installer build 27)
- Branch and commit:
- Automated tests and skips:
- Payload SHA-256 values:
- Glyphs 3.5 build / Python / runtime / result:
- Glyphs 4 build / Python / runtime / result:
- Schema-v4 elapsed time:
- Baseline canonical/native/file restoration:
- Open blockers or accepted limitations:
- Signing: not performed
- Notarization: not performed
- Publication: not performed
```

Passing this protocol produces an unsigned local release candidate, not a
publishable release. Merge, commit, signed tag, signing, notarization, GitHub
draft creation, upload, and publication remain separately authorized actions.
