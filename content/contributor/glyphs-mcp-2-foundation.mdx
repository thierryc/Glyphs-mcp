# Glyphs MCP 2.0 hard-reset foundation

Glyphs MCP 2.0 is a private breaking reset. V1 and Glyphs 3 remain unchanged;
v2 has no public aliases, compatibility wrappers, or transition period.

## Ownership

The architecture has three layers:

1. **Knowledge supplies evidence:** pinned, searchable, cited, version-aware
   font-design, font-engineering, Glyphs API, scripting, plug-in, and format
   information.
2. **Skills supply expertise:** typographic judgment, workflows, calculations,
   exceptions, proofing, and the decision to use declarative mechanics or
   Python.
3. **Tools supply mechanics:** canonical reads, projections, constraints,
   immutable previews, verified writes, history, and explicit external-effect
   boundaries.

The governing rule is permissive expression with strict structural integrity.
Typographic heuristics, locks, alignment configuration, dirty state, and native
Save are never mutation blockers. Ambiguous identities, invalid ownership,
stale live-document fingerprints, unsupported replay, and failed complete
read-back remain hard failures.

## Frozen public surface

The catalog contains exactly 18 tools:

- `get_server_info`, `list_documents`, `read_document`
- `evaluate_constraints`
- `preview_change`, `apply_change`
- `get_operation`, `list_history`, `revert_change`
- `search_knowledge`, `get_knowledge`
- `execute_python`
- `preview_export`, `apply_export`, `save_document`
- `open_document_view`, `get_runtime_status`, `repair_runtime`

MCP discovery generated from the typed transport is the request-schema source
of truth. Catalog definitions are the registration and output-contract source.
The command reference is generated from that catalog. Architecture tests reject
retired endpoint methods, a workflow-solver module, duplicated registration,
and skill references to removed tools.

## Reads and observations

`EntitySelector` owns canonical kind, exact IDs or closed filters, parent
relations, a Boolean predicate AST, typed ordering, generic reducers, and
pagination. Cursors bind selector,
projection, schema version, and document fingerprint. Mutation selectors are
resolved to exact identities during preview.

`Projection` returns requested canonical fields and registry-backed computed
observations with provenance and completeness. Observations cover bounds,
geometry, ownership, alignment, inheritance, grid, horizontal and vertical
spacing, effective metadata, and detached compilation diagnostics.

## Constraints and verified changes

One `Constraint` evaluator serves standalone checks, preconditions,
postconditions, and read-back verification. Assertions compare literals,
current fields, or exact references; they never choose a physical operation.

`ChangeOperation` contains only `set`, `translate`, `insert`, `remove`, `move`,
and `duplicate`. Quantization is explicit. The private structural registry
handles only Glyphs ownership invariants for masters and the master-layer
prefix; it contains no design workflow.

`preview_change` stores exact targets, normalized operations, dependencies,
base live-document and proposed fingerprints, semantic diff, constraint evidence,
warnings, and blockers. `apply_change` consumes that immutable patch without
rerunning planning. Every document mutation passes through detached simulation,
one live apply, complete read-back, verification, rollback on failure, audit,
and history. No operation saves implicitly.

## Save-tolerant persistence

Live-document atomicity and file persistence are separate state domains. A
user may invoke native Glyphs Save before, during, or after any agent action.
Save remains available; a save-only event does not stale a preview, trigger a
permanent incident, or cause the plug-in to undo the save.

Each document has a monotonic save epoch and evidence ledger with native/tool
origin, correlation, timestamps, saved canonical and source-file fingerprints,
decoded saved state, provenance, and completeness. A verified transaction
reconciles the latest saved snapshot:

- saved input: retain the complete live change as unsaved history;
- saved output: audit the operation with no unsaved revert entry;
- saved intermediate: retain only the residual saved-to-live semantic diff;
- unreadable or unexplained source drift: keep tools usable and report a
  persistence warning.

If live verification fails, roll back only the live document and report its
divergence from the latest saved state. `save_document` alone checks file
overwrite preconditions. `expectedDocumentFingerprint`,
`expectedSourceFileFingerprint`, and
`expectedDestinationFileFingerprint` are intentionally distinct.

## Spacing reference

Spacing is an expertise workflow assembled from `read_document` projections,
explicit arithmetic, constraints, `set`, and `translate`. Both axes, bearings,
advance, origin, bounds, geometry translation, grid, metrics inheritance, and
alignment are evidence—not hidden solver inputs. The spacing skill chooses
references, preservation rules, exceptions, and proofs. Signed sidebearing
guidance is cited Knowledge rather than runtime policy.

## Permanent Python

Python is permanent, not a migration escape hatch:

- `read_only` performs bounded inspection on a detached document and proves
  that the live canonical fingerprint and dirty state did not change.
- `staged_document` runs once against a detached font and returns the generic
  immutable preview. `apply_change` applies its stored patch without rerunning
  code.
- `live_open_world` covers unsupported Glyphs APIs, UI, files, processes, and
  other external effects with explicit approval, effect classification,
  checkpoints, and honest recovery evidence.

Generic operations remain preferred when they fit. Skills use Python whenever
they do not.

## Knowledge and skills

The offline Knowledge build records stable IDs, topics, applicable Glyphs
versions, source URLs, authority class, verification dates, checksums,
citations, compatibility notes, and focused code examples. Ranked search and
pagination are deterministic; runtime retrieval never uses uncontrolled
network access.

`skills/` is the only authored skill source.
`plugins/glyphs-mcp/skills/` is generated and checked for exact equality. Every
managed skill follows Knowledge → generic reads → expertise → declarative
preview when expressible → Python fallback when necessary → verification, and
never auto-saves.
